## Overview

Pseudo is a **Medium** HackTheBox **Reversing** challenge — a statically-linked,
stripped **ARM aarch64** ELF, **UPX-packed**, that reads a password from stdin and
validates it with a small bytecode "pseudo" machine. There is no network target; it
is pure offline reverse engineering. The twist for this solve: with no working
`qemu-aarch64` to run the binary, it has to be broken **100% statically** — which is
fine, because the password check is a pure function of each character's position.

## The technique

Two observations make the binary solvable without ever executing an ARM instruction:

1. **Unpack UPX first.** A packed, stripped ELF has *no section headers*, so
   radare2/objdump see nothing. `upx -d` restores all 28 sections
   (`.text`, `.data`, `.rodata`, …). UPX decompression runs on the host, so the guest
   architecture is irrelevant — you can unpack an ARM binary on an x86 box.
2. **The validator is math, not a compare table.** Each expected character is produced
   by a **degree-20 IEEE-754 polynomial** evaluated at the character's index. The
   coefficients sit in `.rodata`. This is Lagrange-fit obfuscation — the coefficients
   *are* the answer.

## Solution

Unpack and disassemble:

```bash
upx -d pseudo -o pseudo.unpacked
r2 -a arm -b 64 -q -c 'e bin.relocs.apply=true; aaa; pd 200 @ 0x400600' pseudo.unpacked
```

The check loop lives at `0x400600`. For each input character (consumed in **reverse**,
last character first, with index `i = 0, 1, 2, …`):

```
transformed = inputchar - 0x5e        ; sub  w2, w0, 0x5e     @ 0x400694
expected    = uint8( poly(i) )        ; fcvtau w0, d8         @ 0x400918
accept if   transformed == expected   ; cmp  w2, w0, uxtb     @ 0x40091c
```

`poly(i)` is a 21-term sum `Σ cₖ·iᵏ` (k = 0..20). The coefficients are the doubles at
`.rodata` `0x400c20..0x400cc0`; the `fmadd` chain at `0x400850` pairs each `pow(i,k)`
with its coefficient. Invert it trivially: `inputchar[i] = (uint8(poly(i)) + 0x5e) & 0xff`.

Reproduce the polynomial from the binary's own constants and reconstruct the password:

```python
import struct

def d(u):  # 64-bit little-endian hex -> IEEE-754 double
    return struct.unpack('<d', struct.pack('<Q', u))[0]

coeff = {
    20: d(0x3d28766e0dcdd4f5), 19: d(0xbd8d59cbf1f29755), 18: d(0x3dd8459c23b87573),
    17: d(0xbe0160a7b0909aa3), 16: d(0xbe516da6a2fee8c9), 15: d(0x3e8683b0964caec2),
    14: d(0x3ecee8ddebf7ca3e), 13: d(0xbf096b2f030d5757), 12: d(0xbf4aa0ea1773f3b8),
    11: d(0x3f90fb3e2768639b), 10: d(0x3fb4fff455b24445), 9:  d(0xc015c17b6f3a3219),
    8:  d(0x4053ab42adf9f03e), 7:  d(0xc0841e44b9202542), 6:  d(0x40aa971512d9a171),
    5:  d(0xc0c76a66ce1099ab), 4:  d(0x40db22200ceaca0e), 3:  d(0xc0e3a70de17c518a),
    2:  d(0x40dfbbddc432ca58), 1:  d(0xc0c549e91fcaa0a3), 0:  d(0x403b00000736d600),
}

def poly(x):
    return sum(c * (x ** k) for k, c in coeff.items())

rev = [((int(round(poly(float(i)))) & 0xff) + 0x5e) & 0xff for i in range(16)]
print("password:", bytes(rev[::-1]).decode('latin1'))
```

```
password: ~vms_all_the_way
```

The binary only prints a **base64 red herring** on success — it decodes to *"you're
still not trying hard enough"*, not the flag. The real flag is the recovered password in
the challenge's canonical leet form (`a → 4`, `e → 3`): `HTB{...}`.

## Why it worked

The password check is data-independent and side-effect-free: every expected byte is a
pure function of its index, baked into `.rodata` as polynomial coefficients. Once you have
those constants you never need to run ARM code — you compute the inverse directly. Packing
with UPX and stripping symbols only raises the bar until you run `upx -d`; the "VM" wrapper
is theatre around a reversible arithmetic map.

## Fix / defense

This is [reliance on obscurity](https://cwe.mitre.org/data/definitions/656.html) (CWE-656).
A "secret" implemented as a floating-point polynomial fit is not secret — the coefficients
are the answer, sitting in the data section for any static reader to lift. A real password
check must be non-invertible: hash the input with a salted KDF (Argon2/bcrypt) and do a
constant-time compare against the stored digest, so recovering the input from the check is
computationally infeasible rather than a line of Python.
