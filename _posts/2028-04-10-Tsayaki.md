## Overview

Tsayaki is a HackTheBox Crypto challenge (Hard, from Cyber Apocalypse 2024). The server runs a TEA-CBC "oracle": for ten rounds you must supply a target ciphertext and **four distinct 16-byte keys** that all encrypt the same fixed message to that one ciphertext. It taunts that "TEA doesn't produce collisions... right?" — it very much does.

## The technique

**TEA equivalent keys.** The Tiny Encryption Algorithm has an effective key size of only 126 bits: XORing `0x80000000` into the most-significant bits of the key-word pair `(k0, k1)` and/or the pair `(k2, k3)` leaves every block's output unchanged. The two flips are independent, so each key has exactly **four equivalent keys** that all encrypt any message to an identical ciphertext under the same IV — precisely the four "collisions" a round demands. This is a [use of a broken/risky cryptographic primitive](https://cwe.mitre.org/data/definitions/327.html) being leaned on for a guarantee (uniqueness) it never provided.

**IV recovery from an error message.** To compute the target ciphertext you need the server's secret CBC `IV`. When a submitted key's result doesn't match your ciphertext, the server helpfully prints its own result: `... but {enc} does not look like {ct}`. Send an **ECB** ciphertext (TEA with no IV) plus a key you control (all zeros); the CBC result differs, so the server echoes the real `enc`. Because TEA is public, decrypt `enc[:8]` with that key and XOR with the first plaintext block to recover the IV (`IV = D_key(enc_block0) XOR msg_block0`). The IV is constant across connections, so recover it once and reuse it.

## Solution

1. **Recover the IV** on one connection using the ECB-vs-CBC error leak.
2. **Farm collisions** on a fresh connection: each of the ten rounds, pick a random base key, compute `ct = TEA(key, IV).encrypt(msg)`, generate its four equivalent keys, and submit `ct` followed by the four keys. Random base keys keep every ciphertext and every key distinct (the server enforces both). After round ten it prints the flag.

```python
#!/usr/bin/env python3
from pwn import remote, xor
from tea import Cipher as TEA
from Crypto.Util.number import bytes_to_long as b2l, long_to_bytes as l2b
import os, sys

HOST, PORT = sys.argv[1], int(sys.argv[2])

def decrypt_block(key, ct):
    m0, m1 = b2l(ct[:4]), b2l(ct[4:]); msk = (1 << 32) - 1
    DELTA = 0x9e3779b9; s = 0xc6ef3720
    K = [b2l(key[i:i+4]) for i in range(0, 16, 4)]
    for _ in range(32):
        m1 = (m1 - (((m0 << 4) + K[2]) ^ (m0 + s) ^ ((m0 >> 5) + K[3]))) & msk
        m0 = (m0 - (((m1 << 4) + K[0]) ^ (m1 + s) ^ ((m1 >> 5) + K[1]))) & msk
        s -= DELTA
    return l2b(((m0 << 32) + m1) & ((1 << 64) - 1))

def eq_keys(key):
    n = l2b(1 << 31)
    k0, k1, k2, k3 = [key[i:i+4] for i in range(0, 16, 4)]
    return [k0+k1+k2+k3, k0+k1+xor(k2,n)+xor(k3,n),
            xor(k0,n)+xor(k1,n)+k2+k3, xor(k0,n)+xor(k1,n)+xor(k2,n)+xor(k3,n)]

def recover_iv():
    io = remote(HOST, PORT); io.recvuntil(b'message: ')
    msg = bytes.fromhex(io.recvline().decode().strip())
    key = b'\x00' * 16
    io.sendlineafter(b'(in hex) : ', TEA(key).encrypt(msg).hex().encode())  # ECB ct
    io.sendlineafter(b'(in hex) : ', key.hex().encode())
    io.recvuntil(b'but ')
    enc = bytes.fromhex(io.recv(48).decode()); io.close()
    return xor(decrypt_block(key, enc[:8]), msg[:8])

def get_flag(iv):
    io = remote(HOST, PORT); io.recvuntil(b'message: ')
    msg = bytes.fromhex(io.recvline().decode().strip())
    for _ in range(10):
        key = os.urandom(16)
        ct = TEA(key, iv).encrypt(msg)
        io.sendlineafter(b'(in hex) : ', ct.hex().encode())
        for k in eq_keys(key):
            io.sendlineafter(b'(in hex) : ', k.hex().encode())
    io.recvuntil(b'really?')
    print(io.recvline().decode().strip())

get_flag(recover_iv())
```

## Why it worked

TEA was never a collision-resistant primitive: it has trivial key collisions (a 126-bit effective key), and CBC's IV is not secret key material — an error message that echoes the computed ciphertext hands you a chosen-key known-plaintext pair, which is enough to invert one block and recover the IV. Using a raw block cipher as if its output were unique is the trap.

## Fix / defense

Never use TEA — or any raw block cipher — where you need collision resistance or uniqueness; use a proper MAC or hash (HMAC, SHA-2). And never echo cryptographic intermediate values (like a computed ciphertext) in error messages.
