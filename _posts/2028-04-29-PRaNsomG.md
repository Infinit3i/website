## Overview

PRaNsomG is a Medium HackTheBox Crypto challenge. You get `ransomware.py` and 32 encrypted business documents; it's entirely offline. The script encrypts each file with AES-CBC, but it draws its key, its IV, and 32 "secrets" (which it appends to the ciphertexts) all from a single `random.Random()` — a Mersenne Twister. MT19937 is not a cryptographic generator, so its state is recoverable from its outputs. The twist here is that the leaked secrets only reveal 576 of the 624 outputs a full clone needs, yet the key and IV are still predictable because they sit at low indices right after the generator's internal twist.

## The technique

Everything comes from one MT stream:

```python
self.secrets = [getrandbits(576) for _ in range(32)]   # leaked
self.key = l2b(getrandbits(1680))[:16]
self.iv  = l2b(getrandbits(1680))[:16]
self.cipher = AES.new(self.key, AES.MODE_CBC, self.iv)  # ONE object, reused
# enc = self.cipher.encrypt(pad(contents,16)) + xor(l2b(secret_i), otp)   # otp = os.urandom(2)
```

Because the CBC object is created once and reused across the loop, all 32 files form **one continuous CBC chain** in filename order `1..32`. Each `.enc` is the AES ciphertext followed by `l2b(secret_i) XOR otp`, a 72-byte tail (a 576-bit integer is 72 bytes); `(filesize - 72) % 16 == 0` confirms the split.

`getrandbits(576)` consumes 18 tempered 32-bit words, assembled least-significant-word first (`word_j = (secret >> 32j) & 0xffffffff`), so 32 secrets give 576 consecutive outputs = MT block words `0..575`. Untempering each output recovers the state word.

The key and IV are outputs `576..681` — past the 576 we have. But at output 624 the MT performs its **twist**, regenerating the block via `new[i] = old[(i+397) % 624] ^ (y>>1) ^ mag[y&1]`, with `y` built from `old[i], old[i+1]`. So a post-twist word `i` depends only on old words `{i, i+1, i+397}`. For `i ≤ 57` those are indices `0..58` and `397..454` — all inside the known `0..575`. And `l2b(getrandbits(1680))[:16]` keeps only the top 16 bytes = the highest (post-twist) words, so the 48 unknown tail words (`576..623`) never affect the key or IV. Set them to zero and reconstruct.

## Solution

```python
#!/usr/bin/env python3
import os, math, random, string
from Crypto.Util.number import long_to_bytes as l2b
from Crypto.Cipher import AES

D = 'enc_files'
files = sorted(os.listdir(D), key=lambda n: int(n.split('_')[0]))
blobs = [open(f'{D}/{f}', 'rb').read() for f in files]
aes_ct = [b[:-72] for b in blobs]
sec_x  = [b[-72:] for b in blobs]

def _undo_rshift(y, s):
    x = y
    for _ in range(math.ceil(32 / s)): x = y ^ (x >> s)
    return x & 0xffffffff
def _undo_lshift(y, s, mask):
    x = y
    for _ in range(math.ceil(32 / s)): x = y ^ ((x << s) & mask)
    return x & 0xffffffff
def untemper(y):
    y = _undo_rshift(y, 18)
    y = _undo_lshift(y, 15, 0xefc60000)
    y = _undo_lshift(y, 7,  0x9d2c5680)   # ceil(32/7) = 5 iters — get this wrong and only the top key byte matches
    y = _undo_rshift(y, 11)
    return y & 0xffffffff

def xorb(a, b):
    return bytes(a[i] ^ b[i % len(b)] for i in range(len(a)))
printable = set(bytes(string.printable, 'ascii'))

for hi in range(256):
    for lo in range(256):
        otp = bytes([hi, lo])
        tempered = []
        for sx in sec_x:
            s = int.from_bytes(xorb(sx, otp), 'big')
            tempered += [(s >> (32 * j)) & 0xffffffff for j in range(18)]
        state = [untemper(t) for t in tempered]
        st = state + [0] * (624 - len(state))
        r = random.Random(); r.setstate((3, tuple(st + [576]), None))
        key = l2b(r.getrandbits(1680))[:16]
        iv  = l2b(r.getrandbits(1680))[:16]
        pt0 = AES.new(key, AES.MODE_CBC, iv).decrypt(aes_ct[0][:16])
        if all(c in printable for c in pt0):
            dec = AES.new(key, AES.MODE_CBC, iv).decrypt(b''.join(aes_ct))
            s = dec.find(b'HTB{'); print(dec[s:dec.find(b'}', s) + 1].decode())
            raise SystemExit
```

Running it brute-forces the 2-byte OTP (`ba3b`), recovers the key and IV, decrypts the continuous chain, and prints the flag:

```console
$ python3 solve.py
HTB{...}
```

## Why it worked

MT19937 is deterministic and fully invertible from its outputs; calling it "secure" changes nothing. The author compounded that by deriving the AES key from the *same* stream whose outputs they leaked — masked only by a 2-byte OTP — and by assuming that leaking fewer than 624 outputs is safe. It isn't when the target outputs sit at low post-twist indices.

## Fix / defense

- Never derive a cipher key from a non-cryptographic PRNG ([CWE-338](https://cwe.mitre.org/data/definitions/338.html)) — use `secrets` / `os.urandom` for keys and IVs.
- Never expose outputs (even truncated or XOR-masked) of the same generator that produces your keys.
- Don't assume "fewer than 624 outputs" hides an MT stream — low post-twist words are predictable from a partial window.
- A one-time pad that is only 2 bytes is a brute-forceable mask, not a pad.
