## Overview

Clutch is an Insane HackTheBox Crypto challenge. A server implements a frame-based [quantum key distribution](https://cwe.mitre.org/data/definitions/320.html) protocol, publishes a public reconciliation transcript, and only reveals the flag if you encrypt a fixed command with the resulting shared key. The "quantum" security is theatre — the transcript discloses enough about the private measurement bases to reconstruct the key exactly, turning an Insane crypto challenge into a solvable constraint puzzle.

## The technique

The server publishes a dictionary `{ double_matchings, frames, sifting_strings, ambiguous_frames }` and then wants `AES-256-ECB(sha256(shared_key))` of `"OPEN THE GATE"`, where the key is a string of `0`/`1` characters.

Reading the source, each key bit is:

```
key_bit          = KEY_DERIVATION[sifting_string][measurement_result]
measurement_result = BOB_MR_DERIVATION[(basis_of_pair0, basis_of_pair1)]
```

`sifting_string` is public. The only unknown is each pair's private measurement basis (X or Z). And those leak as **relations**: every non-ambiguous frame's sifting string ends in measured bits `11`, and its 2-bit prefix says how the frame's two pairs' bases compare — prefix `11` means the bases **differ**, prefix `00` means they **match**. Across all frames, those match/differ facts form a 2-colouring problem.

## Solution

Hand the relations to z3 (one Boolean per pair index, `True` = X, `False` = Z):

```python
from z3 import Bool, Solver, sat, is_true
B = {i: Bool(f"b{i}") for i in pair_indices}
s = Solver()
for (f0, f1), ss in non_ambiguous_frames:
    prefix = ss.split(",")[0]
    if prefix == "11":   s.add(B[f0] != B[f1])   # bases differ
    elif prefix == "00": s.add(B[f0] == B[f1])   # bases match
assert s.check() == sat
m = s.model()
basis = {i: ("X" if is_true(m.evaluate(B[i], model_completion=True)) else "Z")
         for i in pair_indices}
```

`model_completion=True` is required — pairs appearing only in ambiguous frames are unconstrained, and evaluating them otherwise raises "Symbolic expressions cannot be cast to concrete Boolean".

Rebuild the key in the public `frames` order (`frames[i]` corresponds to `sifting_strings[i]`), skipping ambiguous frames. A global X↔Z flip complements every bit, so build both candidates and try each:

```python
def build(basis):
    return "".join(KEY_DERIVATION[ss][BOB_MR_DERIVATION[(basis[f0], basis[f1])]]
                   for (f0, f1), ss in key_frames)
candidates = [build(basis), build({i: ("Z" if b == "X" else "X") for i, b in basis.items()})]
```

Forge the command with either candidate:

```python
from hashlib import sha256
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad
ct = AES.new(sha256(key.encode()).digest(), AES.MODE_ECB).encrypt(pad(b"OPEN THE GATE", 16))
send({"command": ct.hex()})
```

One practical note: the QKD is genuinely simulated in qiskit and is slow and probabilistic (Bob's depolarizing noise is random per attempt, and the server retries until a clean exchange succeeds). A usable transcript appears after roughly a minute or two and one or two retries — connect and wait; only a single round-trip is needed to submit.

## Why it worked

Reconciliation data is the classic QKD side-channel: to agree on a key, the parties exchange *public* information about their private choices. Here the sifting prefix discloses basis relations, and relations over a connected set of symbols pin every basis up to a single global flip. Once the private bases are recovered, replaying the protocol's own derivation tables reproduces the key bit-for-bit.

## Fix / defense

Never publish per-symbol reconciliation data that uniquely determines the private choices. Real QKD reconciliation (Cascade, LDPC) leaks only bounded parity and then applies **privacy amplification** — hashing the sifted key down — precisely so the disclosed information cannot reconstruct the final key. This homemade protocol skipped privacy amplification, so the public transcript *was* the key.
