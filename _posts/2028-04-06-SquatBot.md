## Overview

SquatBot is a Hard HackTheBox Forensics challenge. You get a 1 GB Linux memory dump (`dump.mem`, Ubuntu 4.15) of a compromised AWS-development server and a Volatility profile. A developer went to install the `boto3` AWS SDK but cloned it from a *look-alike* GitHub repo; the fake package's `setup.py` was backdoored and pulled down a **fileless** payload that never touched disk. The malware authenticates to its C2 with a hardcoded password — and that password is the flag. It's a nice tour of a real supply-chain technique: [typosquatting](https://cwe.mitre.org/data/definitions/506.html) into `memfd_create`-based fileless execution, defeated because everything the malware hides from disk is still sitting in RAM.

## The technique

Three links in the chain:

1. **Typosquatting foothold.** The victim `git clone`d `github.com/bootooo3/boto3` (three o's) instead of the real `github.com/boto/boto3` and ran its `setup.py`. Because `pip install` / `setup.py` execute arbitrary Python at install time, one wrong repo name = code execution with the developer's privileges.

2. **Fileless payload.** The backdoored `setup.py` starts with `exec(base64.b64decode('...'))`. Decoded, it opens a socket to a C2, then calls `ctypes.CDLL(None).syscall(319, "", 1)` — **syscall 319 is `memfd_create`**, which creates an anonymous file that lives only in RAM. It streams an ELF over the socket, XOR-decoding each byte, writes it into `/proc/self/fd/{fd}`, and `os.execl`s it. Nothing is ever written to disk, so disk AV and file-integrity monitoring see nothing.

3. **Obfuscated secret.** The dropped ELF builds its C2 password on the stack one chunk at a time with `movabs`/`mov` immediate instructions, where every byte is stored as `plaintext ^ 0x1f`. A single-byte XOR only defeats `strings`; the key sits right next to the ciphertext.

## Solution

Confirm the attack with a few strings and locate the backdoored `setup.py` in the dump — the `exec(base64...)` sits just before the standard `from setuptools` marker:

```bash
strings -n 8 dump.mem | grep -iE "bootooo3|memfd|4443|from setuptools"
grep -a -b -o "from setuptools" dump.mem     # byte offset; the exec() blob is ~1500 bytes before it
```

Decoding that base64 confirms the `memfd_create` (syscall 319) fileless stager, the C2 socket, and the `byte ^ 239` transport decode.

The flag lives as `movabs`/`mov` immediates in the dropped ELF, each byte `^ 0x1f`. Rather than rebuild Volatility, seed the search on the universal `HTB{` prefix — under `^0x1f` those four bytes are `57 4b 5d 64` — then parse the flag-building instruction immediates around it. The durable solver, `solve.py`:

```python
#!/usr/bin/env python3
import sys, re

def find_flag(dump):
    data = open(dump, 'rb').read()
    needle = bytes(c ^ 0x1f for c in b'HTB{')            # 57 4b 5d 64
    off = data.find(needle)
    region = data[off - 48: off + 1100]
    packs, i = [], 0
    while i < len(region) - 9:
        b = region[i]
        if b in (0x48, 0x49) and 0xB8 <= region[i + 1] <= 0xBF:   # movabs reg, imm64
            packs.append(region[i + 2:i + 10]); i += 10; continue
        if b == 0xC7 and region[i + 1] == 0x45:                   # mov dword [rbp-x], imm32
            packs.append(region[i + 3:i + 7]); i += 7; continue
        if b == 0x66 and region[i + 1] == 0xC7 and region[i + 2] == 0x45:  # mov word, imm16
            packs.append(region[i + 4:i + 6]); i += 6; continue
        i += 1
    flag = ''
    for p in packs:
        for by in p:
            c = by ^ 0x1f
            if 0x20 <= c < 0x7f:
                flag += chr(c)
        if flag.endswith('}'):
            break
    return re.search(r'HTB\{[^}]+\}', flag).group(0)

if __name__ == '__main__':
    print('[*] FLAG:', find_flag(sys.argv[1] if len(sys.argv) > 1 else 'dump.mem'))
```

```bash
python3 solve.py dump.mem
# [*] FLAG: HTB{...}
```

The immediates decode, in order, to `HTB{C0mp` `l3t3ly_f` `1l3l3ss_` `but_st1l` `l_d3t3ct` `4bl3` `}` — a message that reads *"Completely fileless but still detectable."*

The intended Volatility route reaches the same place: `linux_bash` shows the typosquat clone, `linux_find_file` pulls the `setup.py`, `linux_lsof` reveals a file descriptor with **no disk path** (the `memfd`), and dumping that memfd gives you the ELF to reverse in Ghidra to the same XOR-`0x1f` stack strings.

## Why it worked

`memfd_create` gives an execution surface that never becomes a file — perfect for evading disk-based defenses. But "fileless" only means "not on disk," and a memory image captures the whole thing: the decoded ELF, the C2 address, and the trivially-obfuscated password all live in RAM. The flag says it out loud — completely fileless, still detectable. The obfuscation (single-byte XOR, hardcoded key beside the data) adds nothing against anyone who dumps memory.

## Fix / defense

- **Pin dependencies** to hashes and install from a trusted/private index: `pip install --require-hashes -r requirements.txt`. Never `git clone` or `pip install` a look-alike package name. Enable typosquat detection on your registry.
- **Hunt the fileless signal:** alert on `memfd_create` (syscall 319) followed by `execveat`/`execl` on `/proc/self/fd/*`, plus unexpected outbound sockets from build/dev hosts (auditd or eBPF).
- **Capture volatile memory before powering off** during incident response — it is the one place fileless malware cannot hide.
