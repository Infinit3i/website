## Overview

AESWCM is a Medium crypto challenge. You submit up to three distinct
"properties"; each is MAC'd with a custom scheme, and the flag drops the instant
two of them share a tag. The MAC turns out to be a XOR-fold of the ciphertext
blocks of a [PCBC](https://en.wikipedia.org/wiki/Block_cipher_mode_of_operation)-encrypted
message — which has no length or order binding, so a three-query trick forges a
collision independent of the unknown key and IV.

## The MAC

```python
def encrypt(self, pt, iv):            # PCBC mode
    xor_block = iv
    ct = []
    for block in blockify(pt):
        ct_block = E(block ^ xor_block)
        xor_block = block ^ ct_block   # PCBC feedback
        ct.append(ct_block)
    return b"".join(ct)

def tag(self, pt, iv):
    blocks = blockify(encrypt(pt, iv))
    random.shuffle(blocks)             # RED HERRING — XOR is commutative
    ct = blocks[0]
    for b in blocks[1:]: ct ^= b
    return ct                          # tag = XOR of all ciphertext blocks
```

`tag(pt) = C₁ ⊕ C₂ ⊕ … ⊕ Cₙ` under a fixed unknown `KEY`/`IV`. The `shuffle`
does nothing — XOR is order-independent. Each property is
`"Property: " + your_hex`, padded to a 16-byte multiple, and the dedup runs on the
**padded** message, so the well-known unpadded/padded collision
(`00` vs `000505050505`) is rejected here (both pad to the same block). You need a
real tag collision between two different padded messages.

## The attack

Track the PCBC E-inputs `Xᵢ`:

```
X₁ = P₁ ⊕ IV,          C₁ = E(X₁)
Xᵢ = Pᵢ ⊕ Pᵢ₋₁ ⊕ Cᵢ₋₁     (i ≥ 2)
```

Two observations dismantle it:

1. A **single-block** message's tag is exactly `C(Q) = E(Q ⊕ IV)` — an
   observable block-cipher oracle that removes the IV from the rest of the attack.
2. With `C(Q)` known you can drive any later block's E-input to a value `Z` of
   your choosing: set `block₂ = R = Q ⊕ C(Q) ⊕ Z`, so
   `X₂ = R ⊕ Q ⊕ C(Q) = Z` and `C₂ = E(Z)`.

That yields a clean, key/IV-independent collision in three queries (with `Z = 0`):

| # | message (blocks) | tag | what you learn |
|---|------------------|-----|----------------|
| R1 | `Q` | `t1 = C(Q)` | `C(Q)` |
| R2 | `Q‖R`, `R = Q⊕C(Q)` | `t2 = C(Q) ⊕ E(0)` | `E(0) = t2 ⊕ C(Q)` |
| R3 | `Q‖R‖S`, `S = Q⊕t2` | `t3 = C(Q) = t1` | **collision** |

In R3, `S = Q ⊕ t2` forces `X₃ = 0 = X₂`, so `C₃ = C₂ = E(0)` and the two blocks
**cancel** in the XOR fold: `tag = C(Q) ⊕ E(0) ⊕ E(0) = C(Q) = t1`. The three
padded messages are 16/32/48 bytes — all distinct — so the dedup is satisfied and
`t3 == t1` prints the flag.

## solve.py (core)

```python
def xor(a, b): return bytes(x ^ y for x, y in zip(a, b))
Q = b"Property: " + b"\x00"*6                      # 16-byte first block

send(Q[10:].hex());           t1 = recv_tag(); CQ = t1          # R1
R = xor(Q, CQ)
send((Q[10:] + R).hex());     t2 = recv_tag()                   # R2  (X2 = 0)
S = xor(Q, t2)
send((Q[10:] + R + S).hex()); t3 = recv_tag()                   # R3  (X3 = 0 = X2)
# t3 == t1  ->  the server prints the flag
```

> `KEY`/`IV` are regenerated per connection, so each fresh connection resets the
> three-query budget — reconnect to re-run. And close-detect on EOF when reading
> the flag: the server closes the socket right after printing it, so a naive
> `while True: recv()` spins forever on empty bytes.

I verified the whole construction across 2000 random keys locally before spending
a single live query.

## Why it worked

- A MAC built as a **XOR of ciphertext blocks** binds neither message length nor
  block order, so any two equal E-inputs cancel to nothing.
- PCBC's feedback becomes known the moment you learn one ciphertext block,
  letting you set later E-inputs to arbitrary values and build a canceling pair.
- The single-block tag *is* `E(Q ⊕ IV)` — a raw block-cipher oracle that erases
  the IV from the problem.

## Fix / defense

- Use a standardized MAC ([HMAC](https://en.wikipedia.org/wiki/HMAC)) or an AEAD
  (AES-GCM) that binds message length and block order — never XOR-fold cipher
  blocks into a tag.
- Don't expose a query that returns a raw `E(block ⊕ IV)`; that's an oracle.
- Deduplicate and compare on canonical ciphertext/tag, not on the input encoding.
