## Overview

One Of Us is a Medium forensics challenge. You get `invisible_shields.docm` (a VBA "spyware" sample) and `mail.txt` — a message the spyware produced, subject *"Outlook Exfiltration Data from User: taustin"*, whose body is a single encrypted blob. Decrypting that blob yields the flag, but the crypto parameters are hidden behind a custom string obfuscator inside the macro.

## The obfuscation

`olevba` dumps the VBA, where every string is produced by one decoder:

```vb
Function nkalPYSrDkoirG(arr, offset)
    key = ovLKcDvvuvaxVc(ActiveDocument.Variables("gtrxGyKtbDzUEDng"))   ' base64-decoded doc variable
    For i = 0 To UBound(arr)
        s = s & Chr(key(i + offset) Xor arr(i))
    Next
End Function
```

So each obfuscated string is `Chr(KEY[offset + i] XOR arr[i])`, and `KEY` is a **base64-decoded Word document variable** stored in `word/settings.xml`:

```xml
<w:docVar w:name="gtrxGyKtbDzUEDng" w:val="eNS7GlezU9snp3ci..."/>
```

## Deobfuscation

Extract that variable (unzip the `.docm`), base64-decode it, and reimplement the decoder in Python — then walk the macro replacing every `nkalPYSrDkoirG(Array(...), N)` with its plaintext:

```python
KEY = base64.b64decode(docvar)
def decode(arr, off): return "".join(chr(KEY[off + i] ^ a) for i, a in enumerate(arr))
```

Two gotchas make or break this: **evaluate the VBA arithmetic** in the arrays (`(114 Xor 242)` → `114 ^ 242`), and **join VBA line continuations (`_`)** before matching calls — the AES key string spans one, so without joining you silently miss it.

The deobfuscated `ydcyecOpBU` reveals the exfil crypto:

```vb
BFSsfIzKNm = FVaFfsygaGuUBB(32)                       ' random 32-char string
Set rij = CreateObject("System.Security.Cryptography.RijndaelManaged")
rij.KeySize   = 256
rij.BlockSize = 256                                   ' Rijndael-256, not standard AES
rij.Mode      = 1                                     ' CBC
rij.Key = UTF8("8xppg2oX68Bo6koL7hwSeC8bCEWvk540")    ' hardcoded 32-byte key
rij.IV  = UTF8(BFSsfIzKNm)                            ' 32-byte IV (256-bit block)
...
ydcyecOpBU = BFSsfIzKNm & "|" & Base64(ciphertext)    ' IV is prepended in the clear
```

## The key insight

The exfil format is **`<32-char IV>` + `"|"` + `base64(ciphertext)`**, so `mail.txt` hands you the IV directly — the only secret you had to recover is the hardcoded key. And the block size is **256 bits** (Rijndael-256), which standard AES libraries can't handle — `pycryptodome`'s AES is fixed at a 128-bit block. A 32-byte IV in .NET `RijndaelManaged` is the giveaway; decrypt with a variable-block Rijndael.

## Solution

```python
import base64, re
from CryptoPlus.Cipher import python_Rijndael     # pip install --break-system-packages pycryptoplus
KEY = b"8xppg2oX68Bo6koL7hwSeC8bCEWvk540"
data = re.search(r'([^\s]+\|[^\s]+)', open("mail.txt").read()).group(1)
iv, ct_b64 = data.split("|", 1)
pt = python_Rijndael.new(KEY, python_Rijndael.MODE_CBC, iv.encode(), blocksize=32).decrypt(base64.b64decode(ct_b64))
print(pt.decode())
```

The plaintext is the stolen email:

```
username: paustin
password: HTB{...}
```

## Why it worked

The spyware's confidentiality rested on a **hard-coded symmetric key** ([CWE-798](https://cwe.mitre.org/data/definitions/798.html)) and an **IV prepended to the ciphertext** — both recoverable from the sample, so an analyst decrypts every exfiltrated message. The macro's only real protection was the reversible XOR string obfuscation keyed off a document variable.

## Fix / defense

- Block macro-enabled Office documents from the internet (Mark-of-the-Web + "disable macros from the internet") — this class of `.docm` spyware dies at the door.
- Alert on Office spawning `CreateObject("...RijndaelManaged")` / `Outlook.Application` and on outbound mail originating from Word.
- Design lesson: never ship a symmetric key inside a client and prepend the IV — use asymmetric crypto or a key server so a captured sample can't decrypt past traffic.

## Tools

`olevba` (dump the VBA), Python (reimplement the XOR-string decoder and evaluate the VBA arithmetic), and `pycryptoplus`'s `python_Rijndael` (Rijndael-256 with a 32-byte block — the one piece standard AES libraries can't do). The whole solve is static; nothing is detonated.
