## Overview

signup is a Medium **Crypto** challenge built on DSA. You get the signing script and a
transcript of 100 signed messages, and the flag is encrypted with the signing key. The
whole challenge hinges on one classic mistake — a **reused nonce** — that leaks the
private key from just two signatures, which then decrypts the flag.

## The technique

DSA signs a message `m` as `s = k⁻¹·(H(m) + x·r) mod q`, where `x` is the long-term
private key and `k` is a per-signature random nonce (`r = gᵏ mod p mod q`). The script
signs 100 messages, prints every `(r, s)`, and — crucially — XOR-encrypts the flag with
the raw private key:

```python
key = long_to_bytes(x)
ctf = repeating_xor_key(flag, key)     # recovering x == decrypting the flag
```

Among the 100 signatures, exactly **one `r` value repeats**. Since `r` is a function of
`k` alone, a repeated `r` means the same `k` was used for two different messages — and
that collapses the security completely.

Given two signatures `(r, s₁)` on `m₁` and `(r, s₂)` on `m₂` sharing the nonce:

```
s₁ - s₂ = k⁻¹·(H(m₁) - H(m₂))   ⇒   k = (H(m₁) - H(m₂)) · (s₁ - s₂)⁻¹  (mod q)
x = (s₁·k - H(m₁)) · r⁻¹  (mod q)
```

## Solution

```python
from collections import Counter
from hashlib import sha512
from Crypto.Util.number import inverse, long_to_bytes

H = lambda m: int(sha512(m.encode()).hexdigest(), 16)   # note: SHA-512, not SHA-256

# find the one repeated r, take its two (message, s) pairs
r = next(r for r, c in Counter(r for _, r, _ in sigs).items() if c > 1)
(m1, s1), (m2, s2) = [(m, s) for m, rr, s in sigs if rr == r]

k = ((H(m1) - H(m2)) * inverse((s1 - s2) % q, q)) % q
x = ((s1 * k - H(m1)) * inverse(r, q)) % q               # the private key

# x is also the repeating-XOR key for the flag
ctf = long_to_bytes(int(ctf_hex, 16))
flag = bytes(c ^ long_to_bytes(x)[i % len(long_to_bytes(x))] for i, c in enumerate(ctf))
print(flag.decode())
```

## Why it worked

A DSA nonce must be **unique and secret** for every signature. Reusing one across two
messages yields two linear equations in the two unknowns `k` and `x`, solvable by hand.
The published `(r, s)` pairs made the reuse trivial to spot (a duplicate `r`), and because
the author reused the private key as a symmetric key, recovering `x` handed over the flag.

## Fix / defense

Generate nonces with **RFC 6979** deterministic derivation (nonce bound to the key and
message, never repeated for distinct messages) or a vetted CSPRNG, and never reuse a
private signing key as an encryption key.
