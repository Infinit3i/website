## Overview

Angler is a **Medium** HackTheBox **Mobile** challenge. You get one `Angler.apk`. The Java layer
is deliberately thin and misleading — the real flag is assembled inside `libangler.so`, a native
JNI library, by a chain of obfuscated C++ string builders. The intended path is a Frida hook on a
device; the shortcut is to just **run the library on your desktop** and let it decode itself.

## The technique

Client-side secret derivation is deterministic and self-contained — a
[reliance on security through obscurity](https://cwe.mitre.org/data/definitions/656.html). Because
the APK ships an `x86_64` ABI copy of the lib, that native code is directly `dlopen`-able on a normal
x86_64 Linux host once its Android (bionic) imports are shimmed. No Frida, no rooted device, no full
static reversal of every obfuscation layer — you execute the real builder and peel only the final
uniform transform.

## Solution

Confirm the flag logic is native with `androguard`:

```java
static { System.loadLibrary("angler"); }
public native String getInfo(String p0);
// BATTERY_LOW receiver -> getInfo( s.d.d("XDR") )   // s.d.d = XOR each byte with 0x10; "XDR" -> "HTB"
```

`getInfo` is a passthrough decoy. `.rodata` holds `HTB{` plus obfuscated blobs; local functions
`a`, `a1`, `a2`, `a3`, `a4` each `operator+` a 14-char fragment onto a `std::string`, while `a()`
pulls `steady_clock::now()`/rand and is a pure decoy. `a1` is the outermost real builder.

Extract the x86_64 lib and drive it directly. `dlopen` first fails with
`version 'LIBC' not found` because bionic imports are versioned `@LIBC`, which glibc does not provide.
Fix it with a forwarding `libc.so` whose version script stamps every export with a `LIBC` version node,
each symbol tail-calling the real glibc function:

Create `libc.ver`:

```
LIBC { global: *; };
```

`libc_all.c` re-exports every undefined symbol under version `LIBC`, tail-calling glibc via
`dlopen("libc.so.6")`. Two non-obvious requirements: export `__sF` as a **data** object (bionic
stdio table), and map bionic `__errno` to glibc `__errno_location` — otherwise `std::stoi`/`strtol`
dereference NULL and crash. Provide empty `libm.so`/`libdl.so`/`liblog.so` stubs (also version `LIBC`).

Create `harness.c` — call the builder via the SysV SRET ABI:

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <dlfcn.h>
#include <stdint.h>
#include <string.h>

static void dump(const char *tag, unsigned char *s) {
    if (!(s[0] & 1)) {                 // libc++ SSO: len = byte0>>1, data at s+1
        size_t len = s[0] >> 1;
        printf("%s '%.*s'\n", tag, (int)len, s + 1);
    } else {                           // long form: len at s+8, char* at s+16
        printf("%s '%.*s'\n", tag, (int)*(uint64_t*)(s+8), *(char**)(s+16));
    }
}

int main(void) {
    void *h  = dlopen("./lib/x86_64/libangler.so", RTLD_LAZY);
    void *gi = dlsym(h, "Java_com_example_angler_MainActivity_getInfo");
    uintptr_t base = (uintptr_t)gi - 0x49e00;          // base = &export - its file offset
    void (*a1)(void*, void*) = (void(*)(void*,void*))(base + 0x49680);
    unsigned char ret[32] = {0}, arg[32] = {0};        // arg = empty std::string (24 zero bytes)
    a1(ret, arg);                                       // rdi = SRET slot, rsi = &arg (by-value = hidden ref)
    dump("a1", ret);
    return 0;
}
```

Build and run — `a1` returns the obfuscated flag; the final layer is a uniform subtract-`0x21`
that yields an ASCII-hex string:

```sh
printf 'LIBC { global: *; };' > libc.ver
gcc -shared -fPIC -fno-builtin -o libc.so libc_all.c -ldl -Wl,--version-script=libc.ver
gcc -shared -fPIC -o libm.so empty.c -Wl,--version-script=libc.ver && cp libm.so libdl.so && cp libm.so liblog.so
gcc -o harness harness.c -ldl
LD_LIBRARY_PATH=. ./harness
# a1 'UYVUUSXcXZWgXVVgTUXSTTVgWXWgWgWUVgTUXUVgWYTQTQWcTRWfTZXe'
python3 -c "s=input();print(bytes.fromhex(''.join(chr(ord(c)-0x21) for c in s)).decode())"
# -> HTB{...}
```

Flag captured live from the running library: `HTB{...}` (redacted).

## Why it worked

The secret and its entire derivation ship in the client. Obfuscation (XOR, additive transforms,
decoy functions, a misleading Java wrapper) only raises effort — the transform is deterministic and
self-contained, so executing the real binary reproduces the flag exactly. Packaging an `x86_64` ABI
variant makes the native lib desktop-`dlopen`-able the moment its bionic imports are stubbed.

## Fix / defense

- Don't derive secrets client-side — validate server-side with a server-held secret or signature; a
  client can always be run or observed.
- If logic must be local, bind it to runtime state a desktop can't fake (Play Integrity / attestation,
  keystore-bound keys) and add anti-hooking / root & debugger detection.
- Drop unused ABI variants (`x86_64`) that make desktop emulation trivial.
- Treat obfuscation as defense-in-depth only, never as the security boundary.
