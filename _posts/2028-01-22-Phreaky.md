## Overview

Phreaky is a Medium **Forensics** challenge. You get a single packet capture and a hint that a mole is *"sending keys to the Talents."* Inside is a run of SMTP emails, each carrying one password-protected zip that holds a slice of a split PDF. Reassemble the slices and the PDF gives up the flag.

## The technique

A protocol overview points straight at email:

```bash
tshark -r phreaky.pcap -q -z io,phs
```

The interesting protocols are **SMTP** and **IMF** (15 emails), all from `caleb@thephreaks.com` to `resources@thetalents.com`, subject *"Secure File Transfer."* Each message is `multipart/mixed` with two relevant parts:

- a text body: *"Attached is a part of the file. Password: `<pw>`"*
- a base64 attachment `<hash>.zip` — a password-protected zip holding one split part `phreaks_plan.pdf.partN`.

So the whole PDF was chopped into 15 pieces, each zipped with its own password, and the passwords were mailed in the clear right beside the ciphertext.

## Solution

The one real gotcha: `tshark`'s **ascii** stream-follow chunks the conversation and corrupts the base64 (byte-count markers get interleaved into the payload). Use **raw** follow and rebuild the client direction only (the non-tab-indented hex lines) to get lossless bytes.

Create `solve.py`:

```python
import subprocess, re, email, os, glob
PCAP = "phreaky.pcap"; os.makedirs("out", exist_ok=True)
streams = subprocess.check_output(["tshark","-r",PCAP,"-Y","smtp","-T","fields","-e","tcp.stream"], text=True)
for s in sorted(set(int(x) for x in streams.split() if x.strip())):
    raw = subprocess.check_output(["tshark","-r",PCAP,"-q","-z",f"follow,tcp,raw,{s}"], text=True)
    cli = bytearray()
    for ln in raw.split("\n"):                       # client bytes = non-tab-indented hex
        h = ln.strip()
        if not ln.startswith("\t") and re.fullmatch(r"[0-9a-fA-F]+", h) and len(h) % 2 == 0:
            cli += bytes.fromhex(h)
    if b"DATA" not in cli or b"base64" not in cli: continue
    body = bytes(cli).split(b"DATA\r\n",1)[1].split(b"\r\n.\r\n",1)[0]
    msg = email.message_from_bytes(body); pw = att = None
    for part in msg.walk():
        if part.get_content_maintype()=="text" and pw is None:
            m = re.search(r"Password:\s*(\S+)", part.get_payload(decode=False) or "")
            if m: pw = m.group(1)
        p = part.get_payload(decode=True)
        if p and p[:2]==b"PK": att = p
    if att and pw:
        open("p.zip","wb").write(att)
        subprocess.run(["7z","x","-p"+pw,"-y","-oout","p.zip"], capture_output=True)
parts = sorted(glob.glob("out/phreaks_plan.pdf.part*"), key=lambda f:int(re.search(r"part(\d+)",f).group(1)))
open("out/phreaks_plan.pdf","wb").write(b"".join(open(p,"rb").read() for p in parts))
print(re.search(r"HTB\{[^}]*\}", subprocess.check_output(["pdftotext","out/phreaks_plan.pdf","-"],text=True)).group(0))
```

```bash
python3 solve.py     # -> HTB{...}
```

Each email's password unlocks its part, the parts concatenate in numeric order into a 2-page PDF, and `pdftotext` reveals the flag (redacted here).

## Why it worked

The archives are password-protected, but the passwords ride the **same cleartext SMTP channel** as the data ([cleartext transmission](https://cwe.mitre.org/data/definitions/319.html)) — a full-recovery exfil where the operator hands you every key. Splitting the file across many small password-zipped attachments hides it from a naive object-export or a quick eyeball, but not from stream reassembly plus a MIME parse.

## Fix / defense

Inspect and egress-filter outbound SMTP for base64 archive attachments, and never transmit a decryption password in the same channel (or in plaintext) as the ciphertext. DLP on `multipart/mixed` messages carrying encrypted zips catches exactly this pattern.
