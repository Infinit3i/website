A car, a tapped serial bus, and one capture file. Unique is a gentle introduction to automotive hacking: the "serial network of the car" is a CAN bus, and the secret we're after is sitting on the wire in the clear. The only real skill is knowing not to fight the file format — and remembering that a shared bus interleaves its talkers.

## Overview

**Category:** Hardware · **Difficulty:** Very Easy

You're handed a single file, `trace_captured.sal` — a Saleae Logic 2 logic-analyzer capture. The prompt says the car's serial network was "tapped into" and packets were collected. That serial network is a **CAN bus** (Controller Area Network), and the flag is transmitted as plaintext ASCII inside the CAN data frames. Decode the capture with the right analyzer, reassemble the bytes per CAN identifier, and the flag falls out — this is textbook [cleartext transmission of sensitive information](https://cwe.mitre.org/data/definitions/319.html).

## The technique

CAN is the bus every modern car uses so its ECUs (engine, dashboard, doors, and so on) can talk to each other. It is a **broadcast, unauthenticated, and unencrypted** protocol — anyone who can tap the two wires, or who is simply handed a capture, can read every message with zero cryptanalysis. Here an ECU is broadcasting a VIN-like secret in plaintext, and that secret is the flag.

Two things trip people up on this "Very Easy" box:

1. **Don't try to hand-parse the `.sal`.** The file is a ZIP of `digital-N.bin` / `analog-N.bin`, but those use Saleae's *proprietary* multi-resolution render format (the analog stream is even padded with a down-sampled "mip pyramid"). Decoding the bytes yourself produces garbage. The reliable decoder is **Logic 2's own CAN analyzer**, which you can drive headlessly over its gRPC automation API — no GUI required.

2. **Reassemble the data bytes *per arbitration ID*.** Every CAN frame carries an identifier, and multiple ECUs multiplex their frames onto the one bus. Concatenating all data bytes in time order interleaves the flag with unrelated telemetry and yields noise. The flag streams entirely under a single identifier (`0x452`); group bytes by ID and it spells out cleanly, repeated many times.

## Solution

First, run Logic 2 headless so its automation API is listening:

```bash
chmod +x Logic2.AppImage
./Logic2.AppImage --appimage-extract
Xvfb :99 -screen 0 1024x768x24 &
DISPLAY=:99 squashfs-root/Logic --automation --no-sandbox --disable-gpu &
```

Wait for the gRPC endpoint on `localhost:10430`, then run the solver:

Create `solve.py`:

```python
#!/usr/bin/env python3
import time, csv, re
from saleae import automation

SAL  = "trace_captured.sal"
OUT  = "/tmp/can_unique.csv"
CHAN = 0          # CAN is single-ended after the transceiver -> ONE channel
BAUD = 125000     # standard CAN bit rate; sweep 120k-130k if you see can_error rows

with automation.Manager.connect(port=10430) as mgr:
    cap = mgr.load_capture(SAL)
    an  = cap.add_analyzer('CAN', label='can',
                           settings={'CAN': CHAN, 'Bit Rate (Bits/s)': BAUD})
    time.sleep(12)                       # let the analyzer process the whole capture
    cap.export_data_table(OUT, analyzers=[an])
    cap.close()

rows = list(csv.reader(open(OUT)))
h = rows[0]; ti, di, ii = h.index('type'), h.index('data'), h.index('identifier')
frames, cur = {}, None
for r in rows[1:]:
    if r[ti] == 'identifier_field':
        cur = r[ii]
    elif r[ti] == 'data_field' and cur is not None:
        v = r[di]
        frames.setdefault(cur, []).append('' if v == '\\0' else v)

for cid, chs in frames.items():
    m = re.search(r'HTB\{[^}]+\}', "".join(chs))
    if m:
        print(f"[id {cid} / 0x{int(cid):x}]  FLAG: {m.group()}")
        break
```

```bash
python3 solve.py
```

The script decodes the CAN traffic, buckets each data byte under the ID of the frame it belongs to, and searches each bucket for the flag:

```
[id 1106 / 0x452]  FLAG: HTB{...}
```

## Why it worked

There is no cryptography here at all — the exercise is "read the wire." The two insights that matter are recognizing that a car's serial capture is CAN (so you reach for the CAN analyzer instead of reverse-engineering a proprietary binary), and realizing that a shared broadcast bus multiplexes senders by arbitration ID, so you must demultiplex by ID before the ASCII lines up.

## Fix / defense

- **Authenticate and encrypt sensitive CAN traffic.** The automotive standard is AUTOSAR SecOC: append a truncated CMAC with a monotonic freshness value (to stop replay) and encrypt the payload. A bus tap then yields only ciphertext plus a MAC the attacker can't forge.
- **Keep secrets off the bus entirely** — hold keys and identifiers in a secure element rather than broadcasting them.
- **Segment the CAN topology** and gateway-filter the OBD-II / external ports so an outsider can't reach internal ECU traffic.
- **Physically harden** the wiring and connectors to raise the cost of attaching a logic analyzer.
