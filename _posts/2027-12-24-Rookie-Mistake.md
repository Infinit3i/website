## Overview

Rookie Mistake is a HackTheBox **Crypto** challenge. The flag is split in half and each half is hidden behind a different "textbook" primitive — an RSA-style encryption and a Diffie-Hellman-style exponentiation. Both are built on primes generated by a helper that *multiplies small primes together*, which makes every group order **smooth**. Smooth order is the whole rookie mistake: it turns a 1000-bit discrete log into a handful of tiny lookups, and it lets an "RSA" modulus that is actually a public prime be inverted with no factoring at all. The break maps to [use of a broken or risky cryptographic algorithm](https://cwe.mitre.org/data/definitions/327.html).

## The technique

The generator is the tell:

```python
def genprime():
    p = 2
    while p.bit_length() < 1020:
        p *= getPrime(30)          # p-1 becomes a product of 30-bit primes -> SMOOTH
    while True:
        x = getPrime(16)
        if isprime((p * x) + 1):
            return (p * x) + 1      # returned prime P has P-1 = 2 * prod(30-bit) * x
```

So for every prime `P` it returns, `P-1 = 2 · (product of 30-bit primes) · (16-bit prime)` — fully smooth, largest factor only 30 bits. The challenge then does two things:

```python
e   = 0x69420
ct1 = pow(flag1, e, p)      # PART 1: "RSA" but the modulus is a PRIME p, not a composite
n   = p * q
g   = 0x69420
ct2 = pow(g, flag2, n)      # PART 2: "DH" over n = p*q
```

**Part 1 — an e-th root modulo a public prime.** Because the modulus is the prime `p` (printed in the clear), there is no factoring problem — `ct1 = m^e mod p` is just an e-th root in the multiplicative group `Z_p*`. With `e = 0x69420 = 2^5·3^3·499` and `p-1` carrying a single factor of 2, `gcd(e, p-1) = 2`, so there are exactly **two** roots. Take the odd part `t = (p-1)/2`, compute `d = e^{-1} mod t`, and `z = ct1^d mod p`. Since `e·d ≡ 1 (mod t)` and `≡ 0 (mod 2)`, the order-2 component cancels and the two candidate roots are simply `z` and `p − z`. Pick the one that decodes to the start of the flag.

**Part 2 — a discrete log over smooth order.** `ct2 = g^flag2 mod n` with `n = p·q`. We already recovered `p` in part 1, so `q = n // p`. Both `p-1` and `q-1` are smooth, so [Pohlig-Hellman](https://cwe.mitre.org/data/definitions/327.html) solves the discrete log mod `p` and mod `q` separately, and the Chinese Remainder Theorem stitches them together. Two traps make or break it: `g` is **not** a primitive root (use its *true* order per prime, skip the factors where it has no component), and `p-1`/`q-1` **share factors** (so the final CRT is over non-coprime moduli and must be merged pairwise with gcd checks).

## Solution

The whole solve is offline — no target, just the provided `gen.py` and `output.txt`. Factoring each smooth `p-1`/`q-1` (about 37 thirty-bit primes) takes a minute or two in pure Python; dump the two factorizations to `p_1.json` / `q_1.json` first, then run:

```python
import re, json, math
from Crypto.Util.number import long_to_bytes, inverse

data = open('files/output.txt').read()
gx  = lambda name: int(re.search(rf'{name}: (0x[0-9a-f]+)', data).group(1), 16)
p, e = gx('p'), 0x69420
cts  = re.findall(r'ct: (0x[0-9a-f]+)', data)
ct1  = int(cts[0], 16)
n, g, ct2 = gx('n'), 0x69420, int(cts[1], 16)

# --- Part 1: e-th root mod prime p. gcd(e,p-1)=2 -> two roots (+-flag1). ---
t = (p-1) >> (((p-1) & -(p-1)).bit_length() - 1)   # odd part of p-1
z = pow(ct1, inverse(e, t), p)                      # = +- flag1
for cand in (z, p-z):
    b = long_to_bytes(cand)
    if b.startswith(b'HTB{'):
        half1 = b[:-69]                             # flag1 = flag_half + urandom(69)

# --- Part 2: dlog of ct2 base g mod n=p*q via Pohlig-Hellman + CRT ---
q = n // p                                          # p known from part 1
fp = {int(k): v for k, v in json.load(open('p_1.json')).items()}   # factorint(p-1)
fq = {int(k): v for k, v in json.load(open('q_1.json')).items()}   # factorint(q-1)

def bsgs(base, h, mod, order):                      # baby-step giant-step in a prime-order subgroup
    m = int(math.isqrt(order)) + 1
    tbl = {}; cur = 1
    for j in range(m): tbl.setdefault(cur, j); cur = cur*base % mod
    fac = pow(inverse(base, mod), m, mod); gamma = h
    for i in range(m):
        if gamma in tbl: return i*m + tbl[gamma]
        gamma = gamma*fac % mod
    raise ValueError

def constraints(g, h, mod, fac):                    # dlog constraints using g's TRUE order per prime
    order = mod - 1; out = []
    for pr, k in fac.items():
        s = 0
        for j in range(1, k+1):
            if pow(g, order // pr**j, mod) != 1: s = j
            else: break
        if s == 0: continue                         # g has no pr-component -> no info
        pk = pr**s
        gi = pow(g, order//pk, mod); hi = pow(h, order//pk, mod)
        x = 0; gamma = pow(gi, pr**(s-1), mod)
        for j in range(s):
            hj = pow(hi * inverse(pow(gi, x, mod), mod) % mod, pr**(s-1-j), mod)
            x += bsgs(gamma, hj, mod, pr) * pr**j
        out.append((x % pk, pk))
    return out

cons = constraints(g, ct2 % p, p, fp) + constraints(g, ct2 % q, q, fq)
X, M = 0, 1                                         # CRT-merge (moduli NOT coprime)
for r, pk in cons:
    gg = math.gcd(M, pk); assert (r - X) % gg == 0
    lcm = M//gg * pk
    X = (X + M * (((r - X)//gg) * inverse(M//gg, pk//gg) % (pk//gg))) % lcm
    M = lcm
assert pow(g, X, n) == ct2
half2 = long_to_bytes(X)[:-200]                     # flag2 = flag_half + urandom(200)
print((half1 + half2).decode())
```

The `assert pow(g, X, n) == ct2` is the live check that the discrete log is correct before it prints the flag:

```
HTB{...}
```

## Why it worked

Everything here rests on **smoothness**. A secure Diffie-Hellman / discrete-log parameter set needs the group order to contain at least one large prime factor; here the order was a product of 30-bit primes, so Pohlig-Hellman reduces a 1049-bit discrete log to a few dozen baby-step-giant-step runs over tiny subgroups. The RSA half never had any secrecy either — encrypting modulo a *public* prime means the "private" operation (an e-th root) is elementary. The flag text says it out loud: *use proper parameters for any cryptosystem*.

## Fix / defense

- **Diffie-Hellman / DLP:** use a safe prime `p = 2q+1` (or a prime-order subgroup) so the group order has a large prime factor — Pohlig-Hellman then costs `O(√largest_factor)`, which is infeasible.
- **RSA:** the modulus must be a hard-to-factor **composite**; a public prime modulus provides zero confidentiality.
- **General:** never build a modulus by multiplying small primes together, and validate at generation time that `p-1` (and any subgroup order) is not smooth. Prefer vetted parameter sets — RFC 3526 MODP groups, standard curves — over a hand-rolled `genprime()`.
