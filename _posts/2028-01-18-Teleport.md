## Overview

Teleport is a Medium **Reversing** challenge (HTB Cyber Apocalypse 2022). You get a single stripped PIE binary that takes a password on the command line and answers either `Looks good to me!` or `Something's wrong...`. The gimmick is its control flow: execution "teleports" around the binary using `setjmp`/`longjmp`, so a straight top-to-bottom read looks hopeless. The trick is realizing the teleport order is a decoy — each hop checks exactly one flag byte, so you can harvest all the checks statically and ignore the jumping entirely.

## The technique

The binary copies `argv[1]` into a fixed global buffer (`BUF = 0x203280`) with `strncpy`, then walks a table of **43 function pointers** (at `0x203020`), calling each once. On that first call, every function does `setjmp(its_own_jmp_buf)` — saving a resume point into a large array of `jmp_buf`s (at `0x203300`, stride 200 = `sizeof(jmp_buf)` on glibc x86-64) — and returns. Think of it as each checker planting a teleport beacon.

`main` then `setjmp`s a **hub** `jmp_buf` (at `0x2031a0`) and dispatches on the returned value:

- one sentinel id → `Looks good to me!` (success),
- another id → `Something's wrong...` (fail),
- anything else → `longjmp(jmp_buf[id], 1)`, i.e. teleport into checker number `id`.

Each teleported-into checker does one comparison:

```c
al = BUF[i];
if (al == C) longjmp(hub, next_id);   // correct char -> teleport onward
else         longjmp(hub, FAIL_id);   // wrong char -> teleport to failure
```

So control bounces hub → checker → hub → checker …, validating one character per hop. But the chain is a red herring: every checker independently encodes a single fact — `flag[i] == C` — and the order it runs in doesn't change those facts. Collect all 43 `(index, char)` pairs and lay them out sorted by index.

## Solution

For each function in the pointer table, two operands give away the check:

- `movzx eax, byte [rip+disp]` — the index is `disp`'s absolute address minus `BUF`,
- `cmp al, 0xNN` — the expected character.

`solve.py` reads the table, disassembles each function with capstone, and reconstructs the flag by index — no dynamic tracing, no z3, no following a single jump:

```python
from pwn import ELF
from capstone import Cs, CS_ARCH_X86, CS_MODE_64

BUF, TABLE, N = 0x203280, 0x203020, 43
e = ELF('teleport', checksec=False)
md = Cs(CS_ARCH_X86, CS_MODE_64)

offs = [int.from_bytes(e.read(TABLE + 8*k, 8), 'little') for k in range(N)]
flag = {}
for off in offs:
    idx = ch = None
    for insn in md.disasm(e.read(off, 68), off):
        if insn.mnemonic == 'movzx' and 'byte ptr [rip' in insn.op_str:
            disp = int(insn.op_str.split('[rip +')[1].split(']')[0].strip(), 16)
            idx = (insn.address + insn.size + disp) - BUF
        elif insn.mnemonic == 'cmp' and insn.op_str.startswith('al,'):
            ch = int(insn.op_str.split(',')[1].strip(), 16)
    if idx is not None and ch is not None:
        flag[idx] = ch

print(''.join(chr(flag[i]) for i in sorted(flag)))
```

Running it yields all 43 indices contiguously and the flag `HTB{...}`. Always verify against the binary rather than trusting the reconstruction:

```bash
./teleport 'HTB{...}'
# Looks good to me!
```

## Why it worked

Scattering the checks through `setjmp`/`longjmp` obfuscates *when* each character is validated, not *what* is validated. The per-byte `cmp al, imm` against a hardcoded constant is fully static — the "teleport" is pure control-flow noise. This generalizes to any "one function per flag byte" obfuscator (jump tables, computed gotos): find the `byte[buf+i]` load and the `cmp`, and drop the dispatch machinery.

## Fix / defense

A secret compiled into a client binary is never secret — [reliance on obfuscation for security](https://cwe.mitre.org/data/definitions/656.html) only raises the RE bar, it does not protect the flag. A real system must validate the password server-side. If a local check is unavoidable, compare a salted hash rather than the plaintext character-by-character, so the expected value never sits in the binary as recoverable constants.
