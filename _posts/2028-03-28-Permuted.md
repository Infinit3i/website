## Overview

Permuted is a HackTheBox Crypto challenge (Medium) that runs a textbook Diffie-Hellman key
exchange — but in the wrong group. Instead of a prime-order subgroup of integers mod `p`, the
"generator" is a random permutation of 50,000 elements, i.e. an element of the symmetric group
`S_50000`. Discrete log is the hard problem that keeps DH secure; in a permutation group it is
trivial, so we recover the private exponent from the public values alone and reconstruct the
shared secret that keys the AES-encrypted flag.

## The technique

`source.py` builds a random permutation `g` of `range(50_000)` and publishes three permutations:

```python
x = list(range(50_000)); shuffle(x)
g = Permutation(x)                 # public generator
A = g ** a                         # public,  a = secret
B = g ** b                         # public,  b = secret
C = A ** b   # == B ** a == g^(ab) # shared secret (never printed)
```

The AES key comes straight from `C`:

```python
sec = long_to_bytes(abs(hash(tuple(C.mapping))))
key = sha256(sec).digest()[16:32]
iv  = b'\xfb\x1d]\xbc...'          # fixed, printed in source
c   = AES.new(key, AES.MODE_CBC, iv).encrypt(pad(FLAG, 16))
```

`output.txt` hands us `g`, `A`, `B`, and the ciphertext `c`. We only need `C = g^(ab) = B^a`.

A permutation decomposes into **disjoint cycles**, and raising a permutation to a power simply
**rotates each cycle**. If a cycle is `(c0 c1 c2 … c_{L-1})` — meaning `g[c0] = c1`,
`g[c1] = c2`, and so on — then

```
g^a  maps  c0 → c[(a) mod L]
```

So for every cycle we read `a mod L` directly: look at where `A` sends the cycle's first
element and find that element's index in the cycle. Each cycle length `L` gives a congruence
`a ≡ r (mod L)`; combine them with the [Chinese Remainder Theorem](https://en.wikipedia.org/wiki/Chinese_remainder_theorem)
to get `a` modulo `lcm(cycle lengths) = ord(g)`. That is enough — the order of `B` divides
`ord(g)`, so `C = B^a` is fully determined. The whole break is `O(n)` over the 50,000 points,
with no square-and-multiply, factoring, or search.

## Solution

The durable artifact is `solve.py` — cycle decomposition, per-cycle discrete log via CRT, then
`C = B^a` by rotating `B`'s cycles, and finally the same key derivation the source uses.

```python
import re, ast
from hashlib import sha256
from math import gcd
from Crypto.Cipher import AES
from Crypto.Util.number import long_to_bytes

def load(name, data):
    m = re.search(rf'^{name} = (\[.*?\])$', data, re.M | re.S)
    return ast.literal_eval(m.group(1))

def cycles(mapping):                        # disjoint-cycle decomposition
    n = len(mapping); seen = [False]*n; out = []
    for s in range(n):
        if seen[s]: continue
        cyc = []; i = s
        while not seen[i]:
            seen[i] = True; cyc.append(i); i = mapping[i]
        out.append(cyc)
    return out

def crt(a1, m1, a2, m2):
    g = gcd(m1, m2); lcm = m1 // g * m2
    inv = pow(m1 // g % (m2 // g), -1, m2 // g)
    return (a1 + ((a2 - a1) // g * inv % (m2 // g)) * m1) % lcm, lcm

def dlog(g, A):                             # recover a with A = g^a
    a_res, a_mod = 0, 1
    for cyc in cycles(g):
        L = len(cyc)
        if L == 1: continue
        pos = {v: i for i, v in enumerate(cyc)}
        r = pos[A[cyc[0]]] % L               # A(c0) = c_{a mod L}
        a_res, a_mod = crt(a_res, a_mod, r, L)
    return a_res, a_mod

def apply_pow(perm, e):                      # perm^e by rotating each cycle
    res = [0]*len(perm)
    for cyc in cycles(perm):
        L = len(cyc)
        for i, v in enumerate(cyc):
            res[v] = cyc[(i + e) % L]
    return res

data = open("output.txt").read()
g = load("g", data); A = load("A", data); B = load("B", data)
c = ast.literal_eval(re.search(r"^c = (b'.*')$", data, re.M).group(1))

a, _ = dlog(g, A)                            # a mod ord(g)
C = apply_pow(B, a)                          # C = B^a = g^(ab)
sec = long_to_bytes(abs(hash(tuple(C))))     # reproduce source key derivation
key = sha256(sec).digest()[16:32]
iv = b'\xfb\x1d]\xbc\r\xa3\x91\x1cvV#\x13\xd8z\xb4\x16'
print(AES.new(key, AES.MODE_CBC, iv).decrypt(c))
```

Running it prints the flag:

```
HTB{...}
```

One subtlety in the key derivation: the challenge relies on Python's built-in
`hash(tuple_of_ints)` being **deterministic across processes**. `PYTHONHASHSEED` only randomizes
hashing of `str`, `bytes`, and `datetime` — integer hashing, and therefore tuple-of-int hashing,
is stable. So `hash(tuple(C))` reproduces the author's value exactly, and the "secret" is in fact
publicly recomputable.

## Why it worked

Diffie-Hellman's security rests on the discrete-log problem being hard *in the chosen group*.
The symmetric group is a perfectly valid group, but its structure — every element is a product of
cycles, and exponentiation just rotates those cycles — hands the exponent to you one cycle at a
time. There is no gap between "public" and "secret" here: `A = g^a` leaks `a mod L` for each cycle
length present in `g`, and CRT stitches those into `a mod ord(g)`.

## Fix / defense

- Instantiate Diffie-Hellman only in groups with a proven-hard discrete-log problem: a large
  prime-order subgroup of `Z*_p`, or a strong elliptic curve such as Curve25519.
- Never hand-roll a "custom group" for key exchange without a hardness argument for its
  discrete-log problem — structured groups (symmetric, matrices over small fields, low-order
  curves) leak the exponent through their structure.
- Don't derive keys from `hash()` of a publicly recomputable object; here the entire secret is
  just `C`, which any observer can rebuild from `g`, `A`, and `B`.
