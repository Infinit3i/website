## Overview

Query is a HackTheBox **Misc** challenge framed as a phishing investigation: you are handed one suspicious 102 KB single-line `htb.js` and asked to "find out more about it." The file is a fake mail-login script whose real logic — and the flag — is buried under **three different JavaScript obfuscators stacked on top of each other**. The intended solve is not to read the obfuscated code but to let the JavaScript engine decode it for you, capturing each layer as text instead of running it. This is a client-side [embedded malicious code / obfuscation](https://cwe.mitre.org/data/definitions/506.html) problem.

## The technique

Every JavaScript obfuscator eventually hands a *string of source* to some `eval`-equivalent and executes it. If you replace that sink with your own function, you capture the next layer as **data** — never running the (potentially malicious) payload. Query stacks three obfuscators, so you interpose three times, each against a different sink:

- **Layer 1 — jjencode.** The file starts `HTB=~[];HTB={___:++HTB,$$$$:(![]+"")[HTB],...}` — classic jjencode with the global renamed from `$`/`_` to `HTB`. It builds source out of `[]{}()!+` and evaluates it. The trick: jjencode reaches `eval` not via the global `Function`, but via `(1).constructor.constructor` (a number's constructor is `Number`, whose constructor is `Function`). So overriding the global `Function` does nothing — you must **shadow `Number.constructor`** with a capturing stub.
- **Layer 2 — Dean Edwards packer.** The captured body is `return"eval(function(p,a,c,k,e,d){...}('...',N,N,'...'.split('|'),0,{}))"` with octal escapes. The packer calls the **global `eval`**, so a `var eval = ...` capturing stub yields the unpacked source.
- **Layer 3 — javascript-obfuscator (obfuscator.io).** The real code: a rotated string array `_0x576b` plus an accessor `_0x2655(idx, key)` that does **custom base64** (lowercase-first alphabet `abc…ABC…0-9+/`) then **RC4** with a per-call key, wrapped in aggressive anti-debug (self-defending wrapper, `debugger`, `constructor`-regex tamper checks). Don't fight the anti-debug — extract only the decoder subgraph (the array, the rotation IIFE, and the `_0x2655` definition) and run just that.

A decoy `https://<base64>.htb/` URL decodes to a fake flag (`HTB{sorry_but_this_is_not_your_flag}`). The real flag is one JSON field the form handler builds, assembled from five decoded tokens and base64-encoded.

## Solution

The whole chain, runnable verbatim, is `solve.js`:

```js
const fs = require('fs'), vm = require('vm');

// L1 jjencode: shadow Number.constructor so the eval sink records the payload string
const src = fs.readFileSync('files/htb.js', 'utf8');
let cap1 = []; let c1 = { __cap: cap1 }; vm.createContext(c1);
vm.runInContext('Number.constructor=function(){__cap.push([].slice.call(arguments));return function(){return ""}};\n' + src, c1);
const body = cap1[0].join('');                       // return"eval(<packed>)"

// L2 packer: eval the string literal, then unpack by stubbing global eval
let c2 = {}; vm.createContext(c2);
vm.runInContext('globalThis.out=' + body.replace(/^return/, ''), c2);
let cap2 = []; let c3 = { __cap: cap2, String, RegExp }; vm.createContext(c3);
vm.runInContext('var eval=function(x){__cap.push(x);return x};\n' + c2.out, c3);
const l3 = String(cap2[0]);

// L3 obfuscator: run ONLY array+rotation+decoder, skip anti-debug, decode the flag field
const core = l3.slice(l3.indexOf('var _0x576b=['), l3.indexOf('var _0x22d365=_0x2655'));
let c4 = { console, String, RegExp, Math, decodeURIComponent, Boolean }; c4.globalThis = c4; vm.createContext(c4);
vm.runInContext(core + "globalThis.F=_0x2655('0x1b','(4jF')+_0x2655('0x45','EkHz')+_0x2655('0x3d','a[hV')+_0x2655('0x2d','L5&s')+_0x2655('0x1a','rQfT');", c4);
console.log(Buffer.from(c4.F, 'base64').toString());  // HTB{...}
```

Running it prints the flag:

```bash
node solve.js
# HTB{...}
```

## Why it worked

Obfuscation only hides code from a *reader*; the JavaScript engine still needs the plaintext source at each `eval` boundary. By interposing on that boundary — `Number.constructor` for jjencode, the global `eval` for the packer, and the isolated RC4 accessor for the final layer — each obfuscator's own runtime becomes your decoder. The last layer's string decoder is a pure function of `(array, index, key)`, so it can be invoked in isolation while all the anti-tamper theatre is left unrun.

## Fix / defense

- **Detection over de-obfuscation:** treat jjencode / packer / javascript-obfuscator signatures (`~[]`, `p,a,c,k,e,d`, `_0xNNNN` arrays, `constructor.constructor`) as high-signal indicators in mail and web gateways — legitimate scripts almost never look like this.
- **Content Security Policy without `'unsafe-eval'`** breaks all three layers, since each one depends on `eval`/`Function`.
- **Sandboxed dynamic analysis:** detonate suspicious JavaScript in an instrumented sandbox that hooks `eval`/`Function`/`document.write` rather than reading the source — exactly the technique used to solve this.
