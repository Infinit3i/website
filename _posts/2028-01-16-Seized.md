## Overview

Seized is a Medium **Forensics** challenge: investigators have imaged a ransomware
operator's `AppData` folder and want the credentials for the group's dashboard. The
dashboard login was saved in Chrome, and Chrome's saved passwords are protected by
Windows **DPAPI** — so the whole solve is an offline DPAPI unwind: crack the user's
masterkey password, decrypt the browser's key, and AES-GCM the stored password.

## Triage

A quick walk of the tree points the way: the ConnectedDevicesPlatform folder is named
`L.ransomoperator`, KeePass had run, and the Chrome profile has one saved login for
`https://windowsliveupdater.com/` (`ransomoperator@draeglocker.com`). Chrome (v80+)
encrypts each `logins.password_value` with AES-256-GCM under a key stored in
`Local State` — and that key is DPAPI-wrapped by the user's masterkey.

## The chain

**1 — Crack the DPAPI masterkey password.** The masterkey files live in
`Roaming/Microsoft/Protect/<SID>/<GUID>`; the active GUID is named in
`Protect/<SID>/Preferred`. Extract and crack:

```bash
DPAPImk2john -mk 'Protect/<SID>/<GUID>' -S '<SID>' -c local > mk.hash   # $DPAPImk$2*... (v2)
hashcat -m 15900 mk.hash /usr/share/wordlists/rockyou.txt               # -> ransom
```

**2 — Decrypt the masterkey:**

```bash
impacket-dpapi masterkey -file '<GUID>' -sid '<SID>' -password ransom
# Decrypted key: 0x138f0895...
```

**3 — Unwrap Chrome's AES key** from `Local State` (base64, strip the 5-byte `DPAPI` prefix):

```python
blob = base64.b64decode(json.load(open("Local State"))["os_crypt"]["encrypted_key"])[5:]
# impacket-dpapi unprotect -file blob -key 0x<masterkey>  ->  46befddb...  (32-byte AES key)
```

**4 — AES-256-GCM decrypt the saved password** from `Login Data` (SQLite). The blob is
`v10` + 12-byte nonce + ciphertext + 16-byte GCM tag:

```python
from Crypto.Cipher import AES
pt = AES.new(aes_key, AES.MODE_GCM, nonce=pw[3:15]).decrypt_and_verify(pw[15:-16], pw[-16:])
```


## Why it worked

DPAPI ties secret protection to the user's logon password. Once that password is a
rockyou word (`ransom`), the iteration count buys nothing and the chain unwinds
end-to-end offline: masterkey → Chrome key → every saved browser password. The same
masterkey would also open `Credentials/`, the `Vault/`, and Wi-Fi keys.

## Fix / defense

Use a strong logon password (DPAPI's KDF can't rescue a dictionary word), store critical
credentials in a real password manager with an independent strong master key, and don't
let the browser save them.
