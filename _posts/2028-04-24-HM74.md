## Overview

HM74 is a Medium HackTheBox **Hardware** challenge (Cyber Apocalypse 2023). You get one file — a SystemVerilog `encoder.sv` — and a `nc` service that is a pure one-way stream: it prints `Captured: <bits>` lines forever and expects nothing back. Each line is the flag re-transmitted as a run of Hamming(7,4) codewords, corrupted by random bit errors. The path is: read the code off the Verilog, syndrome-decode each 7-bit codeword, then majority-vote across many noisy transmissions to average the errors out.

## The technique

Hamming(7,4) is a forward-[error-correcting code](https://cwe.mitre.org/data/definitions/354.html): it packs 4 data bits into a 7-bit codeword with 3 parity bits, which lets a receiver detect and correct any **single**-bit error. The provided encoder tells us the exact bit layout:

```verilog
p0 = data_in[3] ^ data_in[2] ^ data_in[0];
p1 = data_in[3] ^ data_in[1] ^ data_in[0];
p2 = data_in[2] ^ data_in[1] ^ data_in[0];
ham_out = {p0, p1, data_in[3], p2, data_in[2], data_in[1], data_in[0]};
```

That ordering — parity at positions 1, 2, 4 and data at 3, 5, 6, 7 (1-indexed) — is textbook standard Hamming(7,4), so we can use the classic syndrome decoder rather than inventing one.

The catch is the error rate. Hamming(7,4) corrects only one bit per codeword; if a codeword is hit by **two** errors the syndrome points at the wrong position and you silently flip a good bit, producing a plausible-but-wrong character with no warning. No single line decodes cleanly. The fix is redundancy *across* transmissions instead of within a codeword: decode many lines and, for each character position, take a majority vote. Random independent errors never agree, so the correct byte wins every column.

## Solution

For each received 7-bit word `c[0..6]`, compute the three syndrome bits and correct:

```python
def decode7(bits):
    c = [int(b) for b in bits]
    s1 = c[0] ^ c[2] ^ c[4] ^ c[6]   # covers positions 1,3,5,7
    s2 = c[1] ^ c[2] ^ c[5] ^ c[6]   # covers positions 2,3,6,7
    s4 = c[3] ^ c[4] ^ c[5] ^ c[6]   # covers positions 4,5,6,7
    syn = (s4 << 2) | (s2 << 1) | s1  # 1-indexed position of the flipped bit
    if syn:
        c[syn - 1] ^= 1
    return (c[2] << 3) | (c[4] << 2) | (c[5] << 1) | c[6]  # data nibble d3 d2 d1 d0
```

Two decoded nibbles make one ASCII byte (first nibble = high). Then read `Captured:` lines from the socket, decode each into bytes, and vote per byte position:

```python
import socket, re, sys
from collections import Counter

s = socket.socket(); s.connect((sys.argv[1], int(sys.argv[2])))
buf, cols, lines = b"", {}, 0
while lines < 400:
    data = s.recv(65536)
    if not data: break
    buf += data
    while b"\n" in buf:
        line, buf = buf.split(b"\n", 1)
        m = re.search(rb'Captured:\s*([01]+)', line)
        if not m: continue
        bits = m.group(1).decode()
        nibs = [decode7(bits[i*7:i*7+7]) for i in range(len(bits)//7)]
        by = [(nibs[i] << 4) | nibs[i+1] for i in range(0, len(nibs)-1, 2)]
        for i, b in enumerate(by):
            cols.setdefault(i, Counter())[b] += 1
        lines += 1
    if lines >= 50: break

flag = bytes(cols[i].most_common(1)[0][0] for i in sorted(cols))
print(flag.decode('latin1'))
```

Run it against the spawned instance:

```sh
python3 solve.py <docker_ip> <port>
```

It converges in about 50 lines and prints the flag, `HTB{...}`.

## Why it worked

Hamming(7,4) guarantees correction only up to its distance — one bit. The challenge deliberately injects more noise than that per transmission, so any individual decode is unreliable. But the *same message* is broadcast over and over, and the errors are random and independent from line to line. Voting each byte column turns dozens of ~90%-correct copies into one 100%-correct string — classic redundancy-in-time beating redundancy-in-space.

## Fix / defense

Error-correcting codes protect against noise, not against an eavesdropper. FEC redundancy is exactly what let us average the noise away and recover the plaintext. If a transmission is confidential, encrypt it before FEC encoding — never rely on a lossy or noisy channel to keep data secret.
